理由按反馈时刻重算，走 recommendations.py 的 recommendation_reason_key，首页渲染的那句话和面板按它归组的那句话是同一句。复算里的「你标记过想看」只对改过口的行生效：只表过一次态的行，点击本身就是入集合的那个动作，那句话在点击那一刻还没出现。复算还原的是点击那一刻的理由，不是推荐当时的理由——用户在那之后又收藏或浏览过的东西会改变它。

反馈率的分母从这一轮起真正落库：首页每次渲染推荐卡都写一行 `RecommendationImpression`，「被看见」这件事本身进了库，不再拿 `BrowsingHistory` 反推。此前反推的分母是窗口内全部被点开过的商品，一件从搜索点进去的商品也占分母、却没有推荐卡可点，所以反馈率只能报下界。现在仍是下界、只低不高，但偏低的来源只剩三种：反馈的 `updated_at` 可能在窗口外；按钮的动机可能来自窗口外那次看见；曝光表自上线起才开始积累，跨过上线时刻的周期前半段分母是缺的。不和反馈取交集——取交集会让反馈率恒为 100%，这个数字就不存在了。空分母报「—」不报 0%：一周一张卡都没渲染过，反馈率不存在，不是零。

匿名访客的看见也计入分母（`user` 存 null）：首页「为你挑选」对没登录的人照常渲染，只是标题换成「校园里正在被关注」、反馈按钮收起来。不记他们，首页最大的那部分流量就整块不在分母里，反馈率会变成一个只有登录用户才配被统计的数。账号注销后那些看见仍然算数——`user` 取 `SET_NULL`，发生过的看见不该跟着账号一起消失。

两条理由的正反馈比例相差不满 {{ recommendation_quality.metrics.reason_noise_points }} 个百分点视为噪声，同一个量级的理由之间的这点差别，运营看不出来、也动不了手。本面板只报告，不调 +10、不调 0.8、不调 +8、不改任何一句理由文案、不把负反馈的商品加进黑名单。

按分数档和按理由那两处的分子分母仍然都是忽略，报的是忽略自己的形状，不是率——它们回答「什么样的机会被按掉」，上面那张表才回答「多少被看见的机会被按掉」。唯一另一个自带分母的比例是重复忽略占比。

重复忽略的判据是间接的：OpportunityDismissal 上有 (user, demand) 和 (user, lost_found_post) 两个无条件唯一约束，写入走 update_or_create 且 defaults 里只更 expires_at，所以同一个人第二次按「不再显示」不产生新行，只把旧行的 expires_at 往后推 {{ opportunity_dismissal_quality.metrics.silence_days }} 天，created_at 停在第一次按下的时刻。两列距离落在 (30, 35] 天即判为重复忽略。它数不到「第二次忽略恰好也落在第一次附近」的情形，也分不清「用户主动又按」和「别的东西更新了这一行」。

分数在忽略时刻重算，走 demand_matching._match_demand 和 lost_found_matching.score_lost_found_posts 自己，不在运营模块里另写一套。复算取这个用户名下当前在售的商品或活跃的失物记录里分数最高的那一次匹配，还原的是「如果今天再进池，这条机会是多少分」，不是忽略那一刻的分数——用户之后可能把商品下架、降价、改了分类。

本面板不报「先收藏后归类」：Favorite 没有 updated_at，views.update_favorite_collection 走 save(update_fields=['collection'])，模型里也没有任何 auto_now 字段，所以这次保存不刷新任何时间列。一条 60 天前收藏的商品，昨天被移进分组，它在这个库里的全部痕迹就是 created_at = 60 天前、collection = 那个分组——它是什么时候被归类的，不存在。窗口内新建的收藏读出来的 collection 是今天读到的值，不是它创建时的值，报出来会被读成「收藏时就归组率」，而它其实混着大量后来才移进去的收藏。

同理不报分组改名频率：FavoriteCollection 有 updated_at，但应用内没有改名路由——create_favorite_collection 走 get_or_create，同名时不写；update_favorite_collection 改的是 Favorite.collection，不是分组名。唯一写入路径是 Django admin 的保存，所以 updated_at != created_at 只说明「有人在后台动过这条分组」，数不到改名。同理不报删分组之后收藏去哪了：Favorite.collection 是 on_delete=SET_NULL，删分组不删收藏、只把它们变成未分组，而删分组只走 admin，删完的收藏和从来没归过类的收藏长得一模一样。

四类分母各自独立，不能混：当前全部收藏、当前全部分组、当前有收藏的用户、窗口内新建。拿「有收藏的用户」当分母去报分组渗透率，会把没收藏过任何东西的人也算进分母，而他们根本看不到分组功能。「当前」是快照不是窗口，所以窗口内的新建规模和当前快照在面板上分开摆。
