Contribution tier shape

积分等级与徽章的门槛形状

五级等级各自有多少人、七枚徽章各自有多少人拿到，以及哪一类行为在发分

CommunityContribution 是站内唯一一套完整的游戏化体系：六种贡献类型、一份积分权重表、五级积分门槛（CONTRIBUTION_LEVELS）、七枚徽章（CONTRIBUTION_BADGE_RULES），加一条幂等写入（source_key 唯一约束 + get_or_create）。运营侧原本唯一的读者 analytics._build_contribution_insights 只报周期内的积分总量、事件数、人数、按类型分布、每日趋势和前 8 名——全是流量口径，那三张规则表从来没有被任何一个数字碰过。于是一套上线运行的等级体系，运营看不到它的形状。

占比的分母是有过至少一条贡献记录的用户（{{ contribution_tier_shape.user_count }} 人），不是全体用户。第一级门槛是 {{ contribution_tier_shape.level_zero }}，把全体用户当分母会让第一级的占比被大量「从没参与过」的用户撑起来，而那个数说明的是产品渗透率，不是等级门槛的形状。分子 0、分母存在时报 0.0，空分母才报「—」——「一级都没人」和「分母不存在」不是一回事。等级判定直接调产品侧的 _level_for_points，不在本地复制一份。

每一级到下一级，这批人还差多少

{% for row in contribution_tier_shape.gap_rows %} {% endfor %}
跨度停在这一级的人数中位距离最大距离
{{ row.label }} {{ row.distance_count }}{% if row.distance_count == 0 %} 无样本{% endif %} {{ row.mean_distance_label }} {% if row.max_distance is None %}—{% else %}{{ row.max_distance }}{% endif %}

距离 = 下一级门槛 − 这个人现在的积分。跨度对停在同一级的人都一样，距离才因人而异。报中位数和最大值，不报平均值：一个差 200 分的人会把平均值抬起来，而这一节要看的正是「普遍还差多少」。这一级一个人都没停时报「—」不报 0——0 会被读成「差 0 分就升级」，而这里的事实是「这一级一个人都没停」。已停在最高一级的人没有下一级，不进这一节。

六种全列，包括一条记录都没有的类型——漏掉空类型，读者会以为这套体系里只有出现过的几种行为。积分占比的分母是全部积分，不是该类型自己的事件数。单次平均分报实际值，不报代码里的权重常数：两者在有补记或改过历史分值时可能不同，报常数等于把「规则」当成「事实」。

组合数数的是「用户 × 类型」的组合，不是用户数——一个用户可以在六种类型下各出现一次，那是六个组合、一个用户。占比的分母是有过记录的用户数。本模块不判断「异常多的记录」是重复还是真实高频：一个卖家这个月完成了八笔交易，名下就有八条 order:* 记录，这是正常的。给出一个「疑似重复」的结论比不报更糟。

本模块只报告，不改写任何东西。不加迁移、不加字段、不改 CONTRIBUTION_LEVELS、不改 CONTRIBUTION_BADGE_RULES、不改任何分值，不自动调整任何人的等级、不发任何积分、不补发漏记的分。不报「升级用了多久」——库里只有 occurred_at（业务时刻）和 created_at（落库时刻），没有「何时跨过某一级」，两个字段的差本身就是补记噪声。不把「停在低级」读成「不活跃」——积分是特定行为的加权和，一个人完全可能交易频繁但不碰免费赠送和失物招领。不按用户排名、不输出用户名、不读 description（它是商品标题拼出来的自由文本）、不重复 analytics 的周期口径。
