# 商品详情价格轨迹展示设计

## 背景

普通出售商品的每次成功改价已经写入 `ItemPriceChange`，收藏降价提醒负责把“这一次便宜了”告诉买家，运营面板则观察调价方向、幅度和重复调价的供给侧形状。两边跑通后，商品详情页仍然缺少买家视角的可追溯价格信息；买家只能看见当前价格，无法判断这是一口价的稳定报价，还是近期连续调整后的结果。

这轮把已经积累的轨迹谨慎地用于详情页：它不是新的定价证据，也不评价卖家，只是在轨迹足够连续、足够多时，把真实编辑流水转成一张可访问的价格走势图。

## 目标

1. 在普通出售商品详情页增加“价格轨迹”卡片。
2. 用同一份构建结果输出：
   - 一条无 JavaScript 依赖的内联 SVG 走势；
   - 一张按时间升序排列的价格表；
   - 数据边界提示。
3. 轨迹至少 3 条才展示，最多展示最近 6 条，避免一两次编辑被读成完整价格故事。
4. 页面只展示日期，不展示精确调整时间，也不展示操作人。
5. 构建函数保持只读，页面渲染不写回任何业务表。

## 展示门槛

- 只处理 `trade_mode = sale` 且当前出售价格存在的商品。
- 商品必须有至少 3 条连续轨迹：
  - 按时间升序相邻两条轨迹中，前一条 `new_price` 必须等于后一条 `old_price`；
  - 最近一条轨迹的 `new_price` 必须等于商品当前 `price`。
- 任何一环不满足时整卡隐藏，不做降级拼接。直接改库、异常写入或交易方式切换造成的断链，不能被页面伪造成可信历史。
- 已售出或展示过期的商品仍可展示历史轨迹；调价发生时它是真实事实，当前状态只影响交易按钮，不影响历史可解释性。
- 免费赠送和限期借用不展示；这两类交易方式本来就不产生出售价格轨迹。

## 时间与隐私口径

- 轨迹条数按商品全量计数，窗口展示最近 6 条；超过 6 条时明确标注“最近 6 次”。
- 面向买家只显示调整日期，不显示小时和分钟。精确时间能让卖家活跃习惯被反向推断，而价格判断只需要日期粒度。
- 不展示 `changed_by`，不区分是卖家本人还是管理员协助处理；价格是多少比谁点了保存更相关。
- 不显示浏览、收藏、通知或议价数据，不把价格变化解释成热度、诚意或成交概率。
- 功能上线前的历史编辑没有流水，不做回填，也不把第一条轨迹的 `old_price` 称为发布价。

## 走势与表格

- 走势图由服务端生成内联 SVG：
  - 不引入前端图表库，不增加浏览器脚本依赖；
  - 横轴按展示窗口内的记录顺序推进，不按像素距离放大短时间内的多次调价；
  - 纵轴按窗口内最低价与最高价归一化；
  - 起始价和当前价带明显端点；
  - `role="img"` 与 `aria-label` 描述区间和调整次数，表格承担完整数据表达。
- 表格按时间升序输出：
  1. 起始价：窗口内最早一条轨迹的 `old_price`；
  2. 每次调整后的价格；
  3. 当前价：与最近一条轨迹的 `new_price` 相同，不额外发明时间。
- 变化列显示绝对金额和百分比；起始价行显示“窗口起始”，零元基线显示“零元基线”，不算百分比。

## 数据与实施边界

- 新增 `listings/price_history.py`，提供 `build_item_price_history(item)`。
- 查询仅读取当前商品的 `ItemPriceChange`，不建立新的外键、不新增迁移。
- 商品详情视图把构建结果放入上下文，模板在价格参考卡之后渲染。
- 新增 CSS 只负责卡片、走势和紧凑表格的布局与响应式表现。
- 构建函数不捕获数据库错误；详情页原有错误处理保持不变。

## 测试口径

1. 少于 3 条轨迹时返回不可展示状态。
2. 3 条连续轨迹生成起始价、三次调整后价格和当前价。
3. 断链轨迹或当前价格不匹配时整卡隐藏。
4. 超过 6 条时只取最近 6 条，并保留全量计数说明。
5. 免费赠送与限期借用不展示。
6. 零元基线不算百分比。
7. 页面响应包含走势、表格、日期粒度和边界提示，不包含操作人身份。
8. 构建与渲染过程不写任何业务表。

## 后续演进

如果这个卡片被有效使用，再考虑：

1. 卖家侧的轨迹完整性诊断，让断链数据先在维护视角暴露；
2. 更长时间窗口的折叠查看；
3. 与同类价格参考的联合解释。

在这些能力落地前，详情页不输出因果判断，也不给卖家定价建议。
