# 校园地点维护决策留痕设计

## 为什么继续做

`location_maintenance_queue` 已经把四类地点信号排成人工核对顺序，但它只能回答“哪些地
点值得先看”，回答不了后续两个问题：

1. 这一行有没有人看过；
2. 看过之后是已经处理、确认维持现状，还是明确暂缓。

如果没有留痕，维护队列会长期重复同一批信号。运营无法区分“仍待处理”和“已经确认可接
受”，下一次排查只能从零开始。也不能反过来把有决策的行直接隐藏：只要当前信号仍在，
队列就必须继续如实展示，否则看板会把“人工接受过”误变成“信号不存在”。

因此这一轮给队列补一条受控的决策留痕链路。它记录人工判断，不代替人工修改地点档案或
业务外键。

## 目标

- 同一地点、同一组信号只能有一条决策记录；
- 决策结果分成三类：已处理、维持现状、暂缓处理；
- 队列展示当前信号对应的最新决策状态，但不隐藏仍有信号的地点；
- 信号组合变化后，旧决策不再匹配，地点重新回到待核对；
- 决策由管理员在后台留下，记录操作者与时间，供后续审计；
- 队列模块本身仍然只读，不写决策、不改地点、不改业务记录。

## 决策记录

新增 `CampusLocationMaintenanceDecision`：

| 字段 | 说明 |
| --- | --- |
| `location` | 被核对的校园地点，使用 `PROTECT`，避免带决策历史的地点被误删 |
| `signal_fingerprint` | 当前命中信号的稳定指纹，由排序后的信号 key 拼接 |
| `outcome` | `handled` 已处理、`accepted` 维持现状、`deferred` 暂缓处理 |
| `note` | 人工判断说明；维持现状与暂缓必须写清理由 |
| `reviewed_by` | 后台操作者，由保存时的登录管理员自动写入 |
| `created_at` / `updated_at` | 决策创建与最后更新时间 |

唯一约束是 `(location, signal_fingerprint)`。同一地点同一组信号重复核实时，应编辑原决
策，而不是插入一条新记录；地点信号组合变化后，允许出现新的决策行。

### 为什么用信号指纹

队列里的当前引用数会随商品、求购和关注搜索自然变化，不能作为身份。决策要匹配的是
“当时核对的是哪一组问题”，因此指纹只由排序后的信号 key 组成，例如：

```text
duplicate_name|profile_gap
```

这样具有相同问题组合的地点行能找到已有决策；一旦从“近似重名 + 档案缺失”变成“停用
仍被引用”，指纹改变，地点重新待核对。

### 三类结果的边界

- **已处理**：管理员已在相应维护入口完成档案补充、地点开关调整、引用迁移或重名核对；
  本表只留结果，不复述每一步修改。
- **维持现状**：管理员确认当前信号可接受，例如同名地点确实是两栋楼的不同入口，或该
  公共地点暂不需要额外安全提示；必须填写理由。
- **暂缓处理**：当前不处理，但保留后续核对意图；必须填写理由，队列继续显示该行。

三类结果都不修改 `CampusLocation` 或任何业务外键。若管理员在地点后台做了修改，队列会
在下一次构建时重新读取当前事实；如果信号仍在，状态仍是“已复核”，不会伪装成信号消失。

## 队列口径

维护队列继续以当前信号为准，并新增：

- `unreviewed_total`：当前信号没有匹配决策的地点数；
- `reviewed_total`：当前信号匹配到决策的地点数；
- `outcome_totals`：三类决策结果的计数；
- 每行新增 `review_status`、`review_outcome_label`、`decision_updated_at`。

排序规则在原有规则前加一条：同优先级内，待核对地点先于已复核地点。其余仍按当前引用
数、命中信号数、名称稳定排序。

队列不输出操作者用户名，也不在清单里展示自由备注，避免运营看板变成个人清单。备注和
操作者保留在后台决策记录里。

## 后台入口

决策记录通过 Django Admin 维护：

- 列表按更新时间倒序，可按结果、地点、信号指纹筛选；
- 地点名、楼栋、地址可搜索；
- 地点与操作者使用 autocomplete；
- 信号指纹与时间戳只读；
- 保存时自动取当前维护队列的信号指纹，并写入当前登录管理员；
- 当前没有维护信号的地点不允许创建决策，避免留下一条永远匹配不上队列的孤儿记录。

## 边界

- 决策表只保存人工判断，不保存地点快照；地点后续变化仍以当前表为准；
- 不自动清除、合并或拆分地点；
- 不迁移商品、求购、关注搜索外键；
- 不把“已处理”当作信号消失的证明；
- 不把“暂缓”从队列里隐藏；
- 不触发通知，不给学生端增加任何界面；
- 运营看板只输出汇总与地点名等配置信息，不输出操作者或自由备注。

## 测试计划

- 模型：唯一约束、时间戳、字符串表示、维持现状 / 暂缓必须填写理由；
- 指纹：同一信号集合与顺序无关，不同信号集合不同；
- 队列：三类决策都能匹配，未决策地点先排；
- 变化：信号组合变化后旧决策不匹配，地点回到待核对；
- 汇总：复核计数与结果计数不受 20 行清单截断影响；
- 后台：保存自动生成当前指纹、写入操作者，当前无信号地点不能创建决策；
- 只读性：队列构建不修改地点、业务记录或决策记录。
