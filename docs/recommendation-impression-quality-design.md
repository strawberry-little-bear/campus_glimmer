# 首页推荐曝光日志质量

## 要回答的问题

`RecommendationImpression` 上线之后，「首页推荐卡被看见」第一次成为推荐反馈率的落库分母。写入点在 `views.home`：一次渲染最多写八行，走一次 `bulk_create`；写失败只记日志，页面照常返回。这个取舍保护了首页可用性，也让分母存在一个已知的下界——**写失败的这一屏不会出现在表里**。

本模块因此不承诺能数出失败次数。日志没有落到业务表里，看板读不到。它回答的是另一件可以诚实观察的事：**已经落库的曝光行，自身形状是否完整、可归组、可连续使用。**

具体回答四个问题：

1. 周期内有多少行曝光，多少个自然日有写入；
2. 理由 key、分数、位置、时间这些后续分析依赖的字段是什么形状；
3. 同一登录用户反复看见同一件商品的规模有多大，匿名流量单独占多少；
4. 有没有明显违背当前写入契约的行。

## 分析单位与周期

分析单位是 `RecommendationImpression` 的一行：一张推荐卡在一次渲染里被一个访客看见。周期沿用运营看板的本地自然日边界，`created_at` 落在周期开始到当前时刻之间才进入主统计。发生在未来的时间单独列为异常，不并入主统计，也不伪装成周期内流量。

匿名访客是合法数据：首页对未登录用户照常渲染推荐卡，`user` 为空。账号注销后的 `SET_NULL` 也一样，这些行不能标成缺失。

## 可观察与不可观察

可以观察：

- 已落库行的字段完整性；
- 理由 key 是否仍能被当前 `REASONS` 解释；
- 推荐分数是否为零、展示位置是否在当前首页写入范围 1—8 内；
- 时间是否在未来；
- 登录用户 `(user, item)` 的重复曝光形状；
- 按自然日的写入覆盖和最长观测间隙。

不可观察：

- `bulk_create` 的失败次数；
- 一次渲染理论上应写几行、实际少写几行；
- 一次曝光是否真的被用户肉眼看到；
- 匿名访客里哪些行来自同一个人；
- 写入少是首页流量低、没有可推荐商品，还是写入失败。

表里没有渲染批次或请求 ID。因此本模块不按「每屏八张」倒推缺几张，也不把曝光少读成推荐效果差。当前写入范围 1—8 只作为位置异常的检查边界；如果首页推荐改成懒加载、改变每屏数量或增加嵌入位置，必须先改写入契约，再更新这个面板。

## 字段口径

- **理由 key**：空值单列；不在当前 `REASONS` 的 key 单列为「未收录理由」。只报数量和种类数，不输出原始 key，避免把历史代码形态或异常输入当成内容展示。
- **分数**：分数为零单独报告，但不当成缺失。现行推荐分数可以为零：一件上架超过四天、没有收藏、也不匹配用户分类或地点的商品，仍会以「校园新上架」理由进入候选。零既是合法低分，也可能是默认值，面板只把形状摆出来，不替它定罪。
- **展示位置**：小于 1 或大于 8 单列为位置异常。这是当前首页一次渲染最多八张的写入契约，不是对所有未来展示形式的承诺。
- **时间**：主统计只收周期内时间；`created_at` 晚于当前时刻单列为未来时间。
- **用户**：空值单列为匿名/已注销访客，不计入缺失。
- **商品**：外键由数据库约束保证，不额外做「商品缺失」判断。

## 重复曝光

重复不是写入错误。`RecommendationImpression` 刻意不设 `(user, item)` 唯一约束：同一件商品在不同时刻被同一个登录用户看见，是两次独立的看见，折叠会让反馈率分母偏小。

本模块报告：

- 重复涉及的 `(user, item)` 对数；
- 第一次之后多出的重复行数；
- 登录用户重复行占比。

匿名访客没有稳定身份，不把 `(null, item)` 当成同一个人反复看。匿名行只报总量和占比，不进入重复分母，也不推断独立访客数。

## 时间覆盖

按本地自然日报告有写入的天数、无写入的天数和最长观测间隙。它只说明曝光日志的覆盖形状，不说明首页有没有流量。假期、深夜、低流量校园站点都会造成正常间隙；写入失败也会造成间隙，但二者在当前数据模型下不可区分。

## 边界

- 只读 `RecommendationImpression`；
- 不新增表、字段、迁移或渲染批次 ID；
- 不修改首页推荐、写入路径、异常处理和 `bulk_create`；
- 不把结果写回推荐权重、排序、反馈率或风控；
- 不按用户、商品或卖家排名；
- 不输出用户名、商品标题、描述、理由原文之外的异常 key；
- 不把结构形状读成推荐效果；
- 不把时间间隙读成写入失败；
- 不把零分读成缺分，不把匿名读成缺用户。

## 交付

新增只读模块：

```text
listings/recommendation_impression_quality.py
```

运营看板新增「推荐曝光日志质量」，CSV 导出提供同名节和同构表。

## 测试

- 空周期固定结构；
- 周期边界包含开始、排除当前时刻之后的行；
- 匿名行计为合法访客而不是缺失；
- 空理由和未收录理由单列；
- 零分单列但不计为错误；
- 位置 0 与 9 单列；
- 未来时间单列且不进入主统计；
- 登录用户重复曝光按额外行数报告；
- 匿名重复商品不进入登录重复分母；
- 时间覆盖与最长间隙；
- 理由分布使用首页当前文案，不输出异常原始 key；
- 看板与 CSV 同构，且不泄露用户名或商品标题。
