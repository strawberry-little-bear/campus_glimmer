# 毕业季批量发布：CSV / XLSX 导入模板

## 起点

CSV 与 XLSX 导入都采用固定表头，这是为了把解析规则保持到最小、错误定位保持最清楚。但对第一次使用的卖家来说，“固定表头”本身也需要一个可靠来源：手抄表头、改错列名或把说明行放进第一行，都会在导入时变成不必要的挫败感。

第六刀补一个很小的缺口：批量发布页提供模板下载。模板不承载商品数据，也不改变导入边界，只把那一份固定表头和基础输入约束可靠地交给卖家。

## 产品形状

### 入口

批量发布页的导入区域提供两个下载入口：

- CSV 模板
- XLSX 模板

入口只对登录卖家开放。服务端按受控格式参数生成文件，不做静态资源跳转，也不复用任何上传文件。

### CSV 模板

CSV 模板只有一行精确表头：

```text
标题,描述,交易方式,价格,押金,借用天数,成色
```

文件使用 UTF-8、无 BOM、CRLF 换行，并以 `text/csv` 附件返回。无 BOM 是刻意选择：当前解析器要求第一列表头完全等于 `标题`，避免隐形字符制造“看起来一样却解析失败”的问题。习惯使用 Excel 且担心编码问题的卖家应选择 XLSX 模板。

### XLSX 模板

XLSX 模板在内存中生成，只包含一个名为“商品导入”的工作表：

- 第一行仍是完全相同的固定表头；
- 冻结首行，方便滚动时对照列名；
- 按七列内容设置可读列宽；
- 交易方式列第 2 到第 21 行提供下拉选项：`出售`、`免费赠送`、`限期借用`；
- 不放示例商品行，避免卖家忘记删除示例后误发布；
- 不写公式、宏、样式主题或第二个说明工作表。

模板允许最多 20 行商品，与现有批量发布上限一致。金额和天数仍由导入解析器校验，模板只提供输入辅助，不成为第二套规则。

## 响应与安全边界

- 格式只允许 `csv` 和 `xlsx`，其他值返回 404，不做扩展名猜测。
- 文件名固定为 `campus-glimmer-bulk-listing-template.csv` 或 `.xlsx`，不携带用户名、批次或时间戳。
- 响应使用附件 `Content-Disposition`，并设置 `no-store`，避免把个人操作阶段的文件误当作可缓存静态资源。
- 模板生成不读取卖家数据，不写入数据库或媒体目录，不记录下载历史。
- 下载行为不用于卖家标签、信用、排序或运营排名。

## 与导入链路的关系

- 模板表头与 CSV / XLSX 解析器共用同一份常量来源，避免文档、页面和代码各自维护一份表头。
- 下载模板不进入预览 session，不覆盖已有导入草稿。
- 上传后的表头校验、行级错误、token 预览和最终批量发布事务全部保持不变。
- 空模板可以直接上传，但因为没有任何非空商品行，仍会被现有“至少填写一件商品”规则拦下。

## 明确不做的事

- 不做模板库、个人模板保存或最近使用模板推荐。
- 不做列映射、自定义列顺序或多语言表头。
- 不生成 xls 老格式、宏模板或带公式校验的复杂表格。
- 不放示例数据、说明工作表或后台自动填充。
- 不新增模型、字段、迁移、后台任务或下载日志。

## 验收口径

- 登录卖家可以分别下载 CSV 与 XLSX 模板，匿名访问被登录保护拦截。
- CSV 字节内容以精确 UTF-8 表头开头，无 BOM，换行符合声明。
- XLSX 只有一个工作表，第一行表头完全一致，首行冻结，交易方式含受控下拉，无公式和第二工作表。
- 两个模板都能被现有导入解析器识别为“没有非空商品行”的可恢复错误，而不是文件级损坏。
- 未知格式返回 404；下载不写入数据库、媒体目录或 session。
- 全链路不新增模型、迁移、通知或运营排名。
