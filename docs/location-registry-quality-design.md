# 校园地点档案与覆盖质量设计

## 为什么现在做

`CampusLocation` 不是一张只有后台才用的配置表。它同时参与四条用户链路：

1. 商品发布与搜索筛选：`Item.location` 可选，地点为空的商品无法被地点筛到；
2. 求购与关注搜索：`DemandPost.location`、`SavedSearch.location` 都会作为硬条件参与匹配；
3. 交付安排：订单沿用商品地点，双方也能在启用地点里另选交付地点；
4. 安全提示：`is_public` 和 `safety_note` 会告诉学生这个地点是否适合当面交付。

现有模块各自读取这些字段，却没有一个模块回答档案本身的问题：

- `campus_pulse` 只读启用地点，把地点当作供需聚合维度；
- 搜索、求购和交付模块只按地点 FK 过滤，不检查地点档案是否可用；
- 后台能编辑 `building`、`address`、`safety_note`，但没有任何统计读它们的覆盖情况；
- 地点名称有数据库唯一约束，挡不住空白、大小写或 Unicode 归一后相同的近似重名；
- 表单只提供启用地点，历史商品、求购和关注搜索却可能仍指向后来停用的地点。

这些问题的影响方向并不相同。地点档案太少，学生会失去筛选维度；近似重名太多，学生会在两个相似地点之间选错；公共地点没有安全提示，安全卡能给的信息变薄；在售商品缺地点，供给实际存在但地点筛选看不见；启用的关注搜索绑定停用地点，提醒会静默变成永不命中。把它们放在同一个只读面板里，是为了让运营先看见档案结构，再决定是否维护档案。

## 面板要回答的问题

### 1. 档案形状

报告全部地点、启用地点、停用地点、启用且公共、启用但非公共、停用且公共的数量。这里不把“停用且公共”当成错误：停用是选择器可见性，公共是安全语义，两个开关可以同时存在。

### 2. 字段覆盖

只对启用地点统计四类字段的填写率：

- 楼栋 / 校区：`building`
- 详细位置：`address`
- 地点说明：`description`
- 安全提示：`safety_note`

安全提示再按公共 / 非公共拆开。公共地点缺安全提示更值得看，但不自动判定为错误：一个白天开放的图书馆门口可能确实没有需要提醒的门禁信息。

### 3. 当前业务覆盖

用三类当前快照回答“地点到底接没接上业务”：

- 当前在售商品：有地点 / 没地点；
- 活跃求购：有地点 / 没地点；
- 启用关注搜索：绑定启用地点 / 绑定停用地点 / 未限定地点。

没地点不是数据错误：字段是可选的，也可能存在“只想在线沟通”的场景。它只说明这批记录无法参与地点筛选或就近匹配，面板报规模，不把它读成卖家失误。

### 4. 周期交付地点可解释性

对统计周期内的订单，按优先级判断交付地点是否可解释：

1. 订单自己的 `meeting_location`；
2. 交付安排上的 `appointment.location`；
3. 商品当时的 `item.location`。

三处都没有，才报“无可解释地点”。取消订单也照实进分母，因为下单那一刻学生同样需要知道去哪里；但如果订单时间为空或落在窗口外，不进本面板。这里的“可解释”不等于“双方最终见过面”，只表示平台能从现有 FK 里指出一个地点。

### 5. 近似重名自检

数据库唯一约束只保证原文不同。面板用 Unicode NFKC、`casefold()` 和空白折叠归一化名称，再按归一化结果分组：

- 只报告两个及以上启用地点落入同一组的规模；
- 每组列出原文名称、楼栋、地址和当前在售数；
- 不自动合并、不自动改名、不判定哪一个是“正版”。

归一化后仍只有一个成员的地点不进入清单，避免把所有地点都渲染成可疑对象。

### 6. 停用地点仍被当前记录引用

分别统计停用地点仍被以下记录引用的数量：

- 当前在售商品；
- 活跃求购；
- 启用关注搜索。

这是最接近真实故障的一节：表单不会再给出停用地点，但旧记录可以继续引用它。尤其是一条启用的关注搜索绑定停用地点后，地点条件几乎不可能再命中新商品。这里只报引用规模，不改 FK、不把地点重新启用、不给用户发提醒。

## 输出结构

```python
{
    "has_data": bool,
    "summary": {...},
    "field_rows": [...],
    "coverage": {...},
    "delivery_rows": [...],
    "location_rows": [...],
    "duplicate_name_groups": [...],
    "stale_reference_rows": [...],
    "period_days": int,
}
```

- `summary`：档案开关形状；
- `field_rows`：四类字段覆盖，安全提示按公共 / 非公共拆开；
- `coverage`：当前商品、求购、关注搜索的地点覆盖；
- `delivery_rows`：周期订单交付地点来源四档；
- `location_rows`：每个启用地点的档案字段与当前引用数；
- `duplicate_name_groups`：归一化近似重名组；
- `stale_reference_rows`：停用地点仍被当前记录引用的清单。

清单最多列 20 条，并单独给出未展示总数；截断只影响展示，不影响汇总。

## 口径与边界

- 全量地点档案是快照统计，不按周期过滤；
- 交付地点按订单 `created_at` 归入所选周期；
- 只读 `CampusLocation`、`Item`、`DemandPost`、`SavedSearch`、`Order` 和 `MeetingAppointment` 的外键；
- 不新增表、不加字段、不加迁移；
- 不自动合并近似重名、不补写楼栋或地址、不改 `is_active` / `is_public`；
- 不按用户、买家、卖家或申请人聚合，不输出用户名；
- 地点名称、楼栋和地址是配置数据，可以在面板中展示；商品、求购和关注名称不进入输出；
- “覆盖低”或“缺安全提示”只提示维护档案，不自动判错，更不触发通知。

## 测试计划

- 空平台：所有汇总为 0，比例是 `None` 不是 0；
- 开关矩阵：启用 / 停用 × 公共 / 非公共互斥且总数守恒；
- 字段覆盖：四类字段全列，公共与非公共的安全提示分开；
- 当前覆盖：在售无地点、活跃求购无地点、启用关注搜索绑定停用地点各自单列；
- 交付地点：订单地点、安排地点、商品地点、三者皆无四档互斥；
- 近似重名：大小写、全半角和重复空白折叠后能归入同组，原文不同仍保留展示；
- 停用引用：停用地点被当前在售商品或启用关注搜索引用时进入清单；
- 只读性：函数不改动任何地点、商品、求购、关注搜索、订单或交付安排。
