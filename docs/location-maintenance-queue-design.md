# 校园地点维护队列设计

## 为什么现在做

`location_registry_quality` 已经把校园地点档案的四类信号读出来了：

1. 停用地点仍被当前在售商品、活跃求购或启用关注搜索引用；
2. 启用且公共的地点缺少安全提示；
3. Unicode 归一、大小写折叠和空白折叠后出现近似重名；
4. 启用地点缺少楼栋、详细位置、地点说明或非公共地点的安全提示。

这些信号的影响方向不同，不能只给一个总分数。停用引用会让旧记录从选择器里消失，公共地点缺安全提示会削弱交易安全卡，近似重名会让学生选错地点，档案字段缺失主要影响维护效率。运营真正需要的是下一眼先看谁、为什么看它，以及同一地点还有哪些次要信号。

因此这一轮增加一个只读维护队列：它把已有信号转成固定的优先级和行动提示，不自动修复、不自动合并、不改外键，也不把“没被当前业务引用”的启用地点直接判成该删除。

## 队列要回答的问题

### 1. 哪些地点进入队列

只有出现以下四类信号之一的地点进入清单：

- **停用仍被当前引用**：地点已停用，但当前在售商品、活跃求购或启用关注搜索仍指向它；
- **公共地点缺安全提示**：地点启用且 `is_public=True`，但 `safety_note` 为空；
- **近似重名**：两个及以上启用地点在归一化后落入同一名称组；
- **档案字段缺失**：启用地点缺少楼栋、详细位置、地点说明；非公共启用地点缺安全提示也归入这里。

当前引用沿用 `location_registry_quality` 的快照口径：

- 商品：在售，且未过期或没有过期时间；
- 求购：活跃，且未过期或没有过期时间；
- 关注搜索：启用。

交付订单不参与本队列，因为它是历史行为，不是地点档案的当前引用。无地点的商品、求购和关注搜索也不参与：它们没有可指向的地点行，规模继续由上一轮面板负责。

启用但没有上述信号的地点不进队列；停用且没有当前引用的地点也不进队列。它们不是待修复对象。

### 2. 优先级如何定

本队列不做加权评分，不用“严重度分”。一个地点只落入一个主优先级，主优先级按固定顺序取第一个命中的信号：

1. **优先核对**：停用仍被当前引用，或公共地点缺安全提示；
2. **需要分辨**：近似重名；
3. **择期补充**：档案字段缺失。

顺序的理由是：前两类影响学生当下能不能选对地点、能不能读到安全信息；近似重名会造成选择歧义；档案字段缺失主要让维护和沟通变慢，但不一定阻断当前使用。

如果一个地点同时命中多个信号，主优先级只取最高的一类，其他信号保留在该行的次要信号里。因此主优先级行数相加等于队列总数；信号行数相加可以大于队列总数，因为信号允许重叠。

### 3. 同一优先级内如何排序

同一主优先级内按以下顺序排列：

1. 当前引用数多的地点靠前：它影响更多在售商品、活跃求购或启用关注搜索；
2. 命中信号多的地点靠前：处理一次可以同时核对更多问题；
3. 名称靠前的地点靠前，保证同样条件时输出稳定。

这里的“当前引用数”只用于排序，不换算成分数，也不代表故障大小。

### 4. 每行输出什么

每个队列地点输出：

- 地点名、楼栋、详细位置；
- 启用 / 停用、公共 / 非公共；
- 当前在售、活跃求购、启用关注搜索数量；
- 主信号、次要信号、缺失字段；
- 近似重名组的地点数；
- 对应主信号的行动提示。

行动提示只描述需要人工核对什么：

- 停用引用：核对旧记录应迁移、地点应恢复启用，还是保持停用；
- 公共地点缺安全提示：补充提示，或确认该地点确实无需提示；
- 近似重名：核对多个地点是否指同一处，不判断哪一个是“正版”；
- 档案缺失：补齐配置字段，不改业务记录。

## 输出结构

```python
{
    "has_data": bool,
    "summary": {
        "location_total": int,
        "active_total": int,
        "queued_total": int,
        "active_clean_total": int,
        "inactive_clean_total": int,
        "priority_totals": {...},
        "signal_totals": {...},
    },
    "priority_rows": [...],
    "reason_rows": [...],
    "location_rows": [...],
    "location_row_total": int,
    "location_row_limit": 20,
    "location_row_hidden_total": int,
    "period_days": int,
}
```

- `priority_rows`：三个主优先级的互斥计数；
- `reason_rows`：四类信号的重叠计数；
- `location_rows`：最多 20 行的维护清单；
- `active_clean_total` / `inactive_clean_total`：说明多少地点没有进入队列，避免把未列出误读成遗漏；
- `period_days`：随运营看板周期参数返回；本队列本身是当前快照，不用订单周期过滤当前引用。

## 口径与边界

- 只读 `CampusLocation`、`Item`、`DemandPost`、`SavedSearch`；
- 不新增表、不加字段、不加迁移；
- 不修改 `is_active`、`is_public`、地点名称或任何档案字段；
- 不迁移商品、求购、关注搜索的外键；
- 不自动合并近似重名，不判断哪一个是“正版”；
- 不触发通知，不创建维护任务，不把队列写回数据库；
- 不输出用户名，也不输出商品、求购、关注搜索名称；
- 地点名称、楼栋、地址和安全语义是配置数据，可以展示；
- 缺字段、缺安全提示和低引用都只提示核对，不自动判错；
- 清单最多 20 行，截断只影响展示，不影响汇总。

## 测试计划

- 空平台：`has_data=False`，主优先级与信号表仍保持固定结构；
- 入队规则：四类信号各自入队，干净地点不入队；
- 主优先级互斥：同一地点多个信号只计入一个主优先级；
- 信号重叠：信号总数可以大于队列总数；
- 顺序：停用引用和公共安全提示优先于近似重名与档案缺失；
- 排序：当前引用数、信号数、名称共同决定稳定顺序；
- 近似重名：大小写、全半角和重复空白折叠后同组，原文名称保留；
- 公共 / 非公共安全提示分流：公共缺提示是安全信号，非公共缺提示归入档案补充；
- 截断：清单最多 20 行，汇总与隐藏数不受影响；
- 只读性：函数不修改地点、商品、求购或关注搜索；
- 非法周期参数回落 30 天。
