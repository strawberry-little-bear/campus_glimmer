# 商品响应式图片变体设计

## 背景

商品图片链路已经分成两档：列表页读取最长边 480px 的 WebP 缩略图，详情主图读取最长边 1600px 的原图。图片行同时记录原图与缩略图的内在宽高，列表图片可以使用懒加载和异步解码。

这个结构解决了“列表页下载手机原图”的最大问题，但仍然有一个中间缺口：

1. 在 2x / 3x 高分辨率屏幕上，列表卡片如果只拿 480px 小图，可能显得不够清晰。
2. 如果简单地把 480px 小图和 1600px 原图放进 `srcset`，浏览器在高 DPI 下会直接选择原图；一张卡片本来只需要约 600 到 900 像素，却重新下载 1600px 文件，抵消列表小图的收益。
3. 详情主图在桌面端通常也不需要立即加载 1600px 原图，但只有 480px 又明显不够。

因此，这一轮补一个最长边 960px 的预览档，并只在有大图消费需求的图片位置使用 `srcset`。

## 目标

1. 为 `ItemImage` 增加可空的 `preview` 文件字段，以及 `preview_width` / `preview_height` 元数据。
2. 新上传图片在生成 480px 列表缩略图时，若原图最长边超过 960px，同步生成最长边 960px 的 WebP 预览图。
3. 原图最长边不超过 960px 时不生成重复文件，详情和响应式列表直接复用原图。
4. 商品列表和搜索卡片输出：
   - 480px 缩略图与 960px 预览图的 `srcset`；
   - 与实际布局接近的 `sizes`；
   - 既有 `width` / `height`、懒加载和异步解码。
5. 详情主图输出 960px 预览图与原图的 `srcset`，仍然立即加载，不牺牲首图体验。
6. 历史大图通过既有 `backfill_item_thumbnails` 命令分批补齐，不做停机一次性迁移。
7. 生成或回填失败时保留原图可用，页面回退到单 `src`，不让展示失败。

## 非目标

1. 不引入 CDN、AVIF 或按浏览器协商的多容器格式。
2. 不写 JavaScript 图片选择器；浏览器已有 `srcset` / `sizes` 的标准选择能力。
3. 不为 50px 表格缩略图、相关商品小图、公开主页小图增加 `srcset`。这些位置的 CSS 显示尺寸远小于 480px，多给一个候选反而可能诱发额外请求。
4. 不改变上传体积硬限制、原图归一化策略和 480px 缩略图规格。
5. 不自动清理“看起来重复”的历史文件；删除动作必须由明确的字段替换或后台治理完成。

## 数据与生成口径

### 字段

`preview` 允许为空：

- 原图最长边不超过 960px：`preview` 为空，详情使用原图，响应式列表也复用原图。
- 原图最长边超过 960px：保存最长边 960px 的 WebP，并记录方向校正后的宽高。
- 原图读取失败或预览生成失败：清空 `preview` 和预览宽高，详情回退原图。

`preview_width` / `preview_height` 记录浏览器需要知道的内在尺寸，和上一轮新增的原图、缩略图宽高使用同一套语义。

### 图片处理

- 预览图统一转 WebP，质量取 82。
- 生成前应用 EXIF 方向，保存面向浏览器的实际宽高。
- 等比缩放，不放大：最长边 700px 的原图不会生成 960px 文件。
- 960px 只约束最长边，另一边按原比例计算。

### 失败边界

缩略图和预览图是两个独立的最小可用能力：

- 缩略图失败时，列表回退原图，原图仍可保存。
- 预览图失败时，详情回退原图，480px 缩略图和列表页不受影响。
- 替换原图时，两个变体都尝试重建；某个变体失败时清掉对应旧文件，避免新原图配旧变体。

## 页面行为

### 商品列表与搜索卡片

使用：

```html
srcset="480px 缩略图 480w, 960px 预览图 960w"
sizes="(max-width: 576px) 100vw, (max-width: 768px) 50vw, (max-width: 992px) 33vw, 25vw"
```

原因：

- 移动端单列时图片接近全宽；
- 平板两列、桌面三到四列对应 Bootstrap 常见布局；
- 让浏览器根据视口和 DPI 选择 480 或 960，而不是把 1600px 原图带进列表。

没有完整候选宽时只输出单 `src`，不拼不完整的 `srcset`。

### 详情主图

使用 960px 预览图作为默认 `src`，并提供 960 与原图宽度描述符。主图仍然立即加载，`decoding="async"` 保持不变。原图最长边不超过 960px 时直接使用原图。

### 继续只用 480px 的位置

“我的商品”表格、详情页缩略条、同类商品和公开主页商品小图继续保持单 `src`。这些位置的显示尺寸小于或接近 480px，引入 960px 候选不会改善视觉，只会增加选择与请求复杂度。

## 历史回填

继续复用 `backfill_item_thumbnails`，让运维仍然只有一个图片档案命令：

1. 待处理条件包含：
   - 缺 480px 缩略图；
   - 任一展示宽高缺失；
   - 原图最长边超过 960px 且缺预览图。
2. 已有缩略图但缺元数据的行，只读现有文件补宽高，不重复生成。
3. 已有原图宽高的行，可以直接判断是否需要预览图。
4. 需要补预览图时只生成 `preview`，不重建已经存在的缩略图。
5. 命令继续按 `id` 升序支持 `--limit` 和 `--dry-run`，继续把 `marked`、`updated`、`failed`、`skipped` 写入 `TaskRun`。

## 测试口径

1. 大图上传会生成 480px 与 960px 两个变体，并记录三组宽高。
2. 小图上传不生成 960px 重复文件。
3. EXIF 方向图记录的是方向校正后的尺寸。
4. 替换原图会重建变体并删除旧文件。
5. 缩略图失败、预览图失败分别回退且互不拖垮对方。
6. 列表页输出合法 `srcset`、`sizes`、宽高、懒加载和异步解码。
7. 详情主图输出预览图与原图候选，并保持立即加载。
8. 历史大图回填会补预览图；已有缩略图的行不会重复生成缩略图。
9. 坏图不会中断批次，运行台账保留检查、补齐、失败与跳过数量。

## 上线顺序

1. 数据库迁移只增加可空字段，不锁写路径。
2. 应用代码上线后，新上传图片自动生成预览档。
3. 使用 dry-run 查看历史待处理量。
4. 按 `--limit` 分批回填，观察失败与剩余量。
5. 回填完成前，未补到的页面继续使用原图或 480px 图，不出现功能不可用状态。
