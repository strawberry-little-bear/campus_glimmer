# 出售价格轨迹运营口径设计

## 背景

收藏商品降价提醒已经把普通出售商品的每次成功改价写入 `ItemPriceChange`。对买家来说，这是一条提醒；对运营来说，这还是一组新的供给侧事实：卖家在什么时候调整价格、调整幅度有多大、同一件商品是否被反复调价、哪些分类更常出现降价。

这轮不把这些轨迹直接暴露到商品详情页，而是先把它接入运营看板。这样既能观察轨迹数据的真实形状，也能避免在样本尚未积累时把一条内部记录直接变成产品承诺。

## 目标

1. 新增一个只读运营面板，按当前看板周期读取 `ItemPriceChange`。
2. 回答四个问题：
   - 本周期发生了多少次出售价格调整；
   - 降价和上涨各占多少，幅度分布在哪些档位；
   - 调价发生在多少件商品、多少个卖家身上，同一件商品是否被反复调整；
   - 按商品分类看，调价和降价主要出现在哪里。
3. 页面和 CSV 导出共用同一个构建函数，保持屏幕和下载件同构。
4. 继续遵守运营面板纪律：只读、不写回、不自动改价、不给卖家打分。

## 非目标

1. 不回填轨迹功能上线前的历史改价。
2. 不把“第一次记录到的调价”当成商品发布后的第一次真实改价；旧编辑没有流水，不能编造时延。
3. 不读取或展示商品标题、卖家用户名、通知原文和买家收藏名单。
4. 不把降价比例解释成成交率、议价成功率或卖家意愿评分。
5. 不在商品详情页展示价格历史；这个产品口径仍等轨迹积累后单独评估。
6. 不统计免费赠送和限期借用；这两类交易方式本来就不进入价格轨迹。

## 数据与周期口径

- 主数据源是 `ItemPriceChange`，窗口按 `created_at` 落在 `[start, end)` 判断，和运营看板现有周期保持一致。
- 每条轨迹的方向由 `old_price` 与 `new_price` 判断：
  - `new_price < old_price` 记为降价；
  - `new_price > old_price` 记为上涨；
  - 相等行由数据库约束排除，不作为有效输入。
- 调整幅度按 `(new_price - old_price) / old_price` 计算，只保留两位有业务意义的百分比；`old_price = 0` 时分母无效，单独列为“零元基线”，不进幅度分档。
- 幅度档位：
  - 降价：0–5%、5–10%、10–20%、20% 以上；
  - 上涨：0–5%、5–10%、10–20%、20% 以上。
- 商品数和卖家数按窗口内去重，不要求商品当前仍在售；已售出或过期商品的历史调价仍是当时真实的供给侧动作。
- 重复调价按同一商品在窗口内的轨迹条数分为 1 次、2 次、3 次及以上。窗口边缘或功能上线前的记录不可见，所以“多次调价”是下界，不写成完整历史。
- 分类维度读商品当前分类。商品后来改分类时，旧轨迹无法还原当时分类，因此面板把它标成“当前分类视图”，不伪装成历史分类。

## 统计门槛与方向判断

- 少于 12 条有效轨迹时，面板只报规模，不给降价占比、中位幅度或分档方向结论。
- 分类行不足 12 条时只报数字，不给占比方向，延续现有小样本纪律。
- 降价占比的分母是窗口内所有有效轨迹，不是降价商品数；一件商品连续降价两次，代表两次真实调价行为。
- 中位数和 P90 幅度在 Python 侧计算，避免数据库方言差异；输入仍然是过滤后的有限窗口。
- 零元基线只进总览和小样本判断，不进入涨跌幅分档，也不参与中位幅度。

## 页面与导出

面板计划放在供给侧统计附近，输出：

1. 总览：轨迹条数、商品数、卖家数、降价条数、上涨条数、零元基线。
2. 方向与幅度：降价 / 上涨的条数、占比、中位幅度、P90 幅度和档位分布。
3. 重复调价：一次、两次、三次及以上的商品数。
4. 分类视图：分类名、轨迹数、降价数、上涨数、降价占比和小样本标记。
5. 口径提示：无历史回填、分类为当前视图、重复调价为下界、只报告不自动干预。

CSV 导出同名小节和行，不输出清单型敏感字段。

## 测试口径

1. 空数据返回可渲染的空面板，不把缺数伪装成 0%。
2. 降价与上涨分别计数并进入正确幅度档。
3. 零元基线不进入幅度分母。
4. 同一商品多次调价按 1、2、3 次及以上分组。
5. 分类维度按当前分类聚合，小样本只报数字。
6. 商品和卖家按去重口径统计。
7. 页面与 CSV 共享注册表，面板构建失败仍能被现有耗时与注册测试观察到。
8. 模块不写任何业务表。

## 实施边界

- 新增 `listings/price_change_quality.py`，提供 `build_price_change_quality(start, end, now=None)`。
- 注册到 `OPERATIONS_DASHBOARD_SHARED_BUILDERS`，页面和 CSV 共用。
- 不新增模型、不加迁移、不改 `ItemPriceChange` 写入路径。
- 查询使用周期过滤和有限字段读取，避免为了比例统计把业务表整表搬进内存。
