# 毕业季批量发布：XLSX 导入预览

## 起点

CSV 导入第二刀已经证明“先解析、再预览、最后沿用批量发布校验”的链路可靠：导入不直接写商品、不发匹配通知、不给错误行开口子。毕业生整理表格时最顺手的格式仍然常是 Excel 工作簿；如果继续要求他们先另存为 UTF-8 CSV，这条链路的价值会少一截。

第四刀只补文件格式：让同一个上传入口接受 XLSX，并把单元格转换成 CSV 已有的商品行草稿。它不是异步导入，也不是列映射工具。

## 产品形状

### 上传与识别

批量发布页的导入区域从“CSV 文件”改为“CSV / XLSX 文件”。服务端仍只接收一个上传字段，按受控扩展名分发：

- `.csv` 走现有 UTF-8 解析；
- `.xlsx` 走 XLSX 解析；
- 其他扩展名直接返回文件级错误，不做内容猜测。

XLSX 的第一行仍必须完全等于固定表头：

```text
标题,描述,交易方式,价格,押金,借用天数,成色
```

顺序不能调整，不做列映射。解析只读取第一个工作表；后续工作表无论是否有内容，都不参与也不改变结果。页面文案必须明确这一点，避免卖家改错其他工作表后误以为系统没刷新。

### 预览与发布

XLSX 解析成功后复用现有预览机制：

- 跳回批量发布页，商品行进入可编辑预览；
- 分类、地点、专题和展示截止时间仍由本批次共同设置提供；
- 最终提交仍以页面字段为准，重新经过 `BulkListingSettingsForm`、`BulkListingRowForm`、同批次标题去重和事务写入；
- XLSX 草稿与 CSV 草稿共用同一个 session 键和 token 语义，重复上传任意支持格式都会覆盖旧草稿。

导入步骤继续不创建商品、不触发关注搜索或求购匹配通知。

## 文件与单元格边界

### 文件层

- XLSX 不超过 256 KB；超过后提示分批导入。
- 只接受 ZIP 容器和 openpyxl 可读取的标准工作簿；伪扩展名返回文件级错误。
- 解析前检查 ZIP 条目的声明解压规模，解压合计不超过 2 MB，防止小文件展开成异常巨大的表。
- 使用 openpyxl 的只读模式；不执行宏、不计算公式、不请求外部链接、不保存原始文件。
- 第一个工作表最多读取 21 行非空商品：第 21 行用于识别超限，超过 20 行立即返回文件级错误。
- 行级错误最多展示 50 条，与 CSV 保持一致。

### 单元格层

只接受普通文本、整数、小数和空单元格：

- 文本保留原文并去掉首尾空白；
- 数字转换为可放进 Django 表单 initial 的普通十进制文本，不用科学计数法；
- 金额仍最多两位小数，且不小于 0、不超过 99,999,999.99；
- 借用天数必须是 1 到 90 的整数，`14.0` 可以接受，`14.5` 不接受；
- 空单元格等同于空字符串；
- 公式单元格一律拒绝，即使工作簿里存有缓存结果；
- 布尔值、日期时间、错误值、富文本对象和未知类型一律按行级错误处理，不做隐式转换。

这些限制的目的不是覆盖所有 Excel 能力，而是确保进入预览的每个值都能被当前 Django 表单和批量发布校验理解。

## 隐私与滥用边界

- 登录保护、行数上限和商品归属规则与批量发布页完全一致。
- 不保存上传文件名、原始工作簿、单元格坐标日志或导入历史。
- 不新增模型、字段、迁移或后台任务。
- 不把使用 XLSX、导入行数或错误数量用于卖家标签、信用、排序或运营排名。
- 公式和外部引用不会被求值或访问；导入器只关心能安全显示为文本的单元格。

## 明确不做的事

- 不做 xls 老格式、模板生成或列映射配置。
- 不做多工作表选择、合并单元格解释、样式读取或条件格式处理。
- 不做异步任务、断点续传、导入历史或跳过错误行。
- 不做批量图片上传，商品图片仍走发布后的单件编辑和补图队列。
- 不为 XLSX 另建一套发布规则；CSV 和 XLSX 最终都必须走同一套批量发布校验。

## 验收口径

- 登录卖家上传合法 XLSX 后进入预览，数字价格、押金和借用天数显示为普通十进制文本。
- 预览和发布全程不直接创建商品、不触发匹配通知；确认发布才走既有事务。
- 表头不符、非 XLSX、文件超限、解压异常、公式、日期、布尔和错误单元格均有服务端测试。
- 第一个工作表后的其他工作表不改变结果；完全空行继续被忽略。
- 超过 20 行非空商品被拒绝，不生成半成品批次。
- XLSX 与 CSV 共用 token、覆盖和失效语义，最终发布测试覆盖同一闭环。
