# 商品刷新后的搜索回响

## 要回答的问题

卖家点击「刷新」之后，系统只知道两件事：`last_refreshed_at` 被推进，`refresh_count` 加一。至于这次刷新有没有把商品重新带回用户眼前，运营此前只能看供给侧的整体分布，无法回答一件商品在刷新前后发生了什么。

本轮补一张只读对照表：**以每次可观察到的最新刷新为切点，比较刷新前后各 72 小时的搜索曝光、搜索点击、收藏和预约。** 它回答的是刷新前后哪些信号共同变化，不回答「刷新导致了多少点击」。

搜索是这里最合适的主信号：`SearchImpression` 与 `SearchClick` 都是事件表，每次搜索结果页渲染和每次从结果页进入详情页都会留下时间。它们能被精确切到刷新前后，而 `BrowsingHistory` 是每个用户和商品的累计行，只有首次、最近和总次数，没有逐次浏览时间；把这类聚合行硬拆到窗口里会制造看似精确的错误数。

## 分析单位

分析单位是：

```text
商品 × 它当前记录的最近一次刷新
```

当前模型没有刷新历史表，`last_refreshed_at` 只保留最新一次。因此同一商品 earlier 的刷新不能进入样本，也不伪装成「没有发生」；它们只是本次无法观察。

`refresh_count` 是从不清零的累计计数器，而 `refresh_item` 每次成功写入都会加一。所以在最新这条记录上，`refresh_count` 就是这次刷新的序号，从 1 到 4。面板按第 1—4 次固定分四行，0 样本行照列。

## 进入样本的条件

1. `last_refreshed_at` 落在运营看板当前周期内。
2. 刷新时刻距离 `now` 已满 72 小时。
   - 未满窗口的刷新单独报 `immature_refreshes`，不进入前后对照。
3. 商品发布时间早于「刷新前 72 小时窗口」的开始。
   - 发布不足完整前窗的刷新单独报 `no_full_pre_window_refreshes`。新发布带来的自然曝光不能当作刷新前的基线。
4. 刷新时刻本身在发布之后，异常的旧数据不进入样本。

`days` 只决定刷新时刻归入哪个统计周期；72 小时观察窗口固定，不随看板周期变化。

## 前后窗口

对每一次合格刷新：

```text
前窗：refresh_at - 72h <= event_at < refresh_at
后窗：refresh_at <= event_at < refresh_at + 72h
```

前窗不含刷新时刻，后窗含刷新时刻。两个窗口等长、相邻、方向相同，避免把不同长度的计数直接相减。

事件只认四类带发生时间的写入：

- `SearchImpression.created_at`：搜索结果页曝光；
- `SearchClick.created_at`：从搜索结果进入商品详情；
- `Favorite.created_at`：收藏；
- `Order.created_at`：预约。

不使用 `Item.updated_at`，因为任何保存都会推进它；不使用 `BrowsingHistory.view_count`，因为它是累计值；不读商品标题、描述或买卖双方信息。

## 表格口径

按刷新次序固定四行，每行报告：

- 成熟样本数；
- 前窗与后窗搜索曝光总数；
- 后窗每件商品的中位曝光数；
- 前窗与后窗搜索点击率；
- 前窗与后窗收藏数；
- 前窗与后窗预约数；
- 样本是否达到门槛。

点击率的分母是同窗搜索曝光。曝光、点击、收藏和预约是共同变化的描述，不给「提升幅度」打分。搜索整体流量、开学季、专题、关键词变化都可能同时影响两个窗口，因此表格不把后窗高于前窗解释为刷新效果。

每个刷新次序至少 12 件成熟商品才标记为可读样本；不足时数字照报，但不进入任何建议。

## 边界

- 不新增刷新历史表，不补写历史事件，不迁移；
- 不修改 `refresh_item`、`_refresh_state`、排序逻辑或任何写入路径；
- 不自动刷新商品，不调整刷新额度；
- 不按卖家、商品或分类排名；
- 不输出用户名、商品标题、订单号或搜索词；
- 不计算相关系数，不估计因果提升，不写回推荐、信誉或风控；
- 不把未满 72 小时的刷新读成失败；
- 不把后窗无曝光解释成刷新无效。

## 交付

新增只读模块：

```text
listings/refresh_response.py
```

运营看板返回值新增 `refresh_response`，页面在刷新额度相关面板附近新增「商品刷新后的搜索回响」，CSV 导出提供同构表和口径说明。

## 测试

- 空周期固定四行；
- 刷新次序与 0 样本行保留；
- 未满 72 小时的刷新单列，不进对照；
- 发布不足完整前窗的刷新单列，不进对照；
- 前窗与后窗边界不重叠、不漏刷新时刻；
- 搜索曝光和点击分别进入对应窗口；
- 点击率使用同窗曝光作分母；
- 收藏与预约按各自发生时间归窗；
- 12 件商品样本门槛；
- 输出不包含用户名、商品标题、订单号或搜索词；
- 看板与 CSV 同构。
