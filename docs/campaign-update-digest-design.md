# 校园专题更新订阅与上新摘要设计

状态：已完成，已接入页面、通知、运营看板、CSV 与定时任务  
更新日期：2026-10-18  
关联模块：校园专题报名、站内通知、通知偏好、定时任务、运营看板

## 1. 这轮要解决什么

校园专题报名已经让用户能够表达“我想持续关注这个活动”，但现有报名仍然只是一条静态记录：用户加入后，除非主动回到专题页面，否则不会知道专题里刚刚上架了什么；运营也无法判断“报名之后还有多少人愿意继续接收活动更新”。

本轮把专题报名扩展成一条可持续、可退出的关注关系，但边界保持不变：

- 报名不等于预约商品，不锁定库存，不创建订单；
- 加入专题不会自动订阅提醒；
- 只有用户主动打开“专题上新摘要”后，系统才会生成站内通知；
- 摘要只汇总新上架商品，不逐件推送；
- 用户退出专题、专题结束或关闭通知偏好后，待发送内容不再投递；
- 默认每日最多一条摘要，也可以选择每周。

## 2. 产品原则

### 2.1 两次同意，不偷换语义

“加入专题”与“订阅更新”是两次独立选择。前者表达参与意愿，后者表达接收站内摘要的明确同意。页面文案和测试都必须保持这一点，避免用户以为自己只是加入活动，却被默认加入了消息列表。

### 2.2 每个周期合并，不做商品级轰炸

一个用户在同一频率、同一周期内最多收到一条专题摘要。多个专题的命中会合并到同一条通知里；通知只列出少量标题，并引导用户进入“我的专题足迹”查看整体情况。

### 2.3 退出门槛低，退出后立即失效

摘要发送不读取一份独立的营销名单，而是实时校验报名区间、专题窗口、商品可用状态和全局通知偏好。退出专题后，即使缓冲表里仍有旧命中，也不会再发送。

### 2.4 可重跑，不重复打扰

商品进入专题时写入幂等的事件缓冲；摘要发送使用“频率 + 周期 + 用户”永久去重键，重复运行命令不会产生第二条通知。新命中若在当日摘要发出后才到达，会留到下一个周期，而不是补发第二条。

## 3. 数据模型

### 3.1 `CampaignRegistration` 扩展

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `notify_updates` | Boolean | `False` | 是否主动订阅该专题的新上架摘要 |
| `update_frequency` | Char | `daily` | `daily` 或 `weekly`，只在订阅开启时生效 |

订阅状态放在当前活跃报名上，不新增独立订阅表。原因是订阅的生命周期天然跟随一次参与区间；退出即停止，重新加入后重新选择，也保留历史区间可解释性。

### 3.2 `CampaignUpdateMatch`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `registration` | FK `CampaignRegistration` | 接收该命中的参与区间 |
| `item` | FK `Item` | 新进入专题的商品 |
| `matched_at` | DateTime | 商品被识别为专题新上架的时间 |
| `notified_at` | DateTime(null) | 实际进入摘要的时间 |
| `cancelled_at` | DateTime(null) | 退出订阅、专题结束或商品失效后取消的时间，保留审计但不投递 |
| `notification` | FK `Notification`(null) | 生成并关联的摘要通知 |

约束：

- `registration + item` 唯一，避免同一参与区间重复入队；
- 按 `registration, notified_at` 建索引，支持按用户和待发送状态扫描；
- 按 `notification` 和 `matched_at` 建辅助索引，支持运营统计和问题排查。

## 4. 入队规则

以下入口必须调用同一套领域服务：

1. 普通发布商品并选择专题；
2. 编辑商品，从其他专题或不挂专题改为挂到当前专题；
3. 批量发布商品并设置共同专题；
4. 批量把已有商品加入或移动到专题。

服务只处理同时满足下列条件的事实：

- 商品存在专题；
- 专题当前仍在进行；
- 商品状态为 `available`；
- 商品没有过期；
- 当前存在 `is_active=True AND notify_updates=True` 的报名；
- 同一报名与商品尚未入队。

同一商品从专题 A 移到专题 B 时，B 下会生成新的命中；A 下尚未发送的旧命中在摘要筛选时因商品已不归属 A 而失效。编辑标题、价格或描述但不改专题，不会重复入队。

## 5. 摘要发送规则

候选报名必须同时满足：

- `is_active=True`；
- `notify_updates=True`；
- `update_frequency` 与本次命令频率一致；
- 专题 `is_active=True`，已经开始且尚未结束。

候选命中还必须满足：

- `notified_at IS NULL` 且 `cancelled_at IS NULL`；
- 商品仍为 `available`；
- 商品未过期；
- 商品当前仍属于该报名对应的专题。

发送时按用户合并所有专题命中，检查：

1. 全局 `NotificationPreference.campaign_update`；
2. 用户当前是否处于免打扰时段。

任一项不满足时不创建通知，也不回写 `notified_at`，命中会保留到后续运行再判断；按正常每日一次调度，通常顺延到下个周期。免打扰时段与现有通知中心保持一致：消息不进入免打扰期间的顶部未读提醒，但专题摘要按更严格的产品约束直接跳过本次发送，避免用户在休息时间收到累积消息。

摘要去重键：

```text
campaign-update-digest:<daily|weekly>:<period>:<user_id>
```

每日使用本地日期，每周使用 ISO 年与周。命令重复执行时，先检查该周期是否已经发送。

## 6. 命令与调度

```bash
python manage.py send_campaign_update_digest
python manage.py send_campaign_update_digest --frequency daily
python manage.py send_campaign_update_digest --frequency weekly
```

命令通过 `record_task_run` 写入任务台账，并输出：

- 发送摘要数；
- 因全局偏好关闭而跳过的用户数；
- 处于免打扰时段的用户数；
- 没有待发送命中的订阅数；
- 已失效商品或专题的命中数。

建议每日摘要每天运行一次，每周摘要在每周一运行一次；两者可以放在同一条调度命令中，也可以使用 `--frequency` 分开调度。

## 7. 页面与运营口径

### 专题详情

活跃报名用户可以：

- 打开或关闭专题上新摘要；
- 选择每日或每周；
- 看到“摘要不预约商品、不占库存”的明确说明。

### 我的专题足迹

展示每个当前专题的订阅状态与频率，并提供修改入口。退出专题时无需额外确认，旧订阅随参与区间一起失效。

### 通知偏好

增加“校园专题更新摘要”全局开关，纳入现有免打扰设置和通知类型覆盖检查。

### 运营看板

专题表现增加：

- 当前订阅人数；
- 待发送命中数；
- 周期内已发送摘要数；
- 摘要已读数与阅读率。

订阅只代表“愿意接收活动更新”，不能进入预约率或成交率的分子、分母；阅读率也不代表购买意向。

## 8. 非目标

- 不自动推荐用户加入专题；
- 不自动改变专题状态或结束时间；
- 不根据点击、订阅或阅读行为调整商品排序；
- 不把订阅用户加入私信、邮件或外部营销渠道；
- 不逐件推送专题商品；
- 不为用户生成排名或公开订阅关系。

## 9. 验收清单

- 加入专题不会自动订阅；
- 用户只能为当前活跃报名修改订阅；
- 关闭订阅、退出专题、专题结束、关闭全局偏好后都不再发送；
- 每日和每周各自按周期去重；
- 同一周期重复运行不重复发送；
- 多个专题命中合并为一条用户摘要；
- 同一商品不重复入队；
- 已售、已预订、过期和已移出专题的商品不进入摘要；
- 普通发布、编辑挂专题、批量发布、批量分配均可入队；
- 匿名用户不能修改订阅，GET 不会改变状态；
- 通知类型、偏好字段和表单字段保持一致；
- 运营指标只描述触达和阅读，不暗示库存或成交。
