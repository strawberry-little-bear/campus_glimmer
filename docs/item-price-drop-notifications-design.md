# 商品降价提醒与价格轨迹设计

## 背景

心愿单已经能把商品重新放回用户的注意力里，但买家和卖家之间仍有一个常见断点：买家觉得价格不合适，先收藏等一等；卖家后来降价，买家却没有任何主动提醒，只能反复回到详情页刷新。

现有生命周期模块会提醒“价格高于同类常见区间”的卖家考虑调价，但它服务的是供给侧建议，不知道一次真实降价是否发生，也无法把这次变化告诉已经表达过兴趣的买家。

这一轮补上这条链路：记录商品的出售价格变化，并在真实降价时提醒收藏过该商品的用户。

## 目标

1. 为商品增加价格轨迹表，记录一次成功编辑前后的出售价格。
2. 只有普通出售商品记录价格轨迹；免费赠送和限期借用的价格不是交易谈判字段，不进入这套口径。
3. 价格上调也留轨迹，方便后续展示可追溯的价格历史；但只触发降价提醒。
4. 当普通出售商品的价格从高变低，并且商品当前仍可购买时，通知收藏过该商品的用户。
5. 每个用户可以继续在通知偏好里单独关闭“收藏商品降价”提醒。
6. 卖家本人收藏自己的商品不收到提醒。
7. 价格变化与通知生成的边界清晰，通知失败不阻断卖家保存编辑。

## 非目标

1. 不做议价、出价、到价提醒和自动砍价。
2. 不把收藏人列表、收藏时间或买家的观望行为暴露给卖家。
3.不自动给所有历史商品补价格轨迹；第一版只从新编辑开始记录。
4. 不在商品详情页展示价格历史；等轨迹积累后再单独设计展示口径。
5. 不追踪后台直接改库或绕过表单的历史改价；这不是可靠业务事件。
6. 不比较免费赠送、借用押金或赠送后的线下结算价格。

## 数据口径

新增 `ItemPriceChange`：

- `item`：外键到商品，删除商品时级联删除轨迹。
- `old_price` / `new_price`：各保留两位小数，记录表单保存前和保存后的出售价格。
- `changed_by`：记录执行编辑的用户，用户删除后允许为空。
- `created_at`：价格变化落库时间。

约束：

1. `old_price` 与 `new_price` 不相等，价格未变不写空轨迹。
2. 轨迹按编辑成功顺序保留，价格上调和下调都进入同一张表。
3. 同一次编辑只写一条轨迹，图片、描述、地点等其他字段变化不触发。
4. `trade_mode` 必须是 `sale`。免费赠送和限期借用的价格字段不代表买家应付金额。

## 触发流程

1. 卖家进入商品编辑页，视图先保留当前数据库中的旧价格。
2. 商品表单校验通过并保存后，若价格发生变化，写入一条 `ItemPriceChange`。
3. 商品若因补齐新的展示截止时间而重新上架，先完成状态修正，再判断是否发送降价提醒。
4. 只有同时满足以下条件才通知：
   - 交易方式仍为普通出售；
   - 新价格低于旧价格；
   - 商品状态为在售且展示未过期；
   - 收件人当前收藏该商品；
   - 收件人开启了对应通知偏好。
5. 通知挂上同一个商品对象，点击后进入商品详情页，消息中写明旧价格、新价格和下降金额。

## 通知口径

新增通知类型 `item_price_drop`，中文名“收藏商品降价”。

- 每次价格变化对每个收藏者最多生成一条通知。
- 去重键包含价格轨迹 ID，同一收藏者在同一次降价中不会重复收到。
- 如果卖家连续两次降价，这是两个真实事件，应生成两条提醒；用户可用通知偏好控制整体开关。
- 通知偏好新增同名布尔开关，默认开启。
- 免打扰时段沿用现有规则：只压制顶部徽标和实时提醒，不删除通知中心里的记录。

## 失败与一致性

- 商品保存和价格轨迹写入放在同一个数据库事务里；轨迹写不进去时，这次编辑失败回滚，避免出现“价格已变但没有来源记录”。
- 通知生成在轨迹成功落库后执行，单个收件人的偏好或通知写入失败不应让卖家编辑失败。
- 不追补历史降价；历史里没有完整编辑流水，靠当前价格反推会制造假历史。

## 测试口径

1. 出售商品降价会写入轨迹，并通知收藏者。
2. 价格上调写入轨迹，但不发降价提醒。
3. 价格不变、免费赠送、限期借用不写轨迹。
4. 已过期商品降价不提醒；补齐未来展示时间并重新上架后可以提醒。
5. 卖家收藏自己的商品不提醒。
6. 关闭偏好的收藏者不提醒，开启者正常提醒。
7. 连续两次降价分别生成轨迹和通知。
8. 非卖家无法通过编辑路径触发通知。
9. 通知类型、偏好字段和偏好表单三处名单保持对齐。
