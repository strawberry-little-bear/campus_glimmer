# 分类调价参考聚合

## 起点

商品详情页已经有 `build_price_insight`：一件出售商品可以看见同类商品的中位数、四分位区间、自己的位置，以及一个“可以考虑调整”的提示。这个能力解决了卖家单件商品的视角，但运营侧仍然看不见分类层面的形状。

真实问题不是“这一件贵不贵”，而是：

1. 哪些分类里有一批当前在售商品都落在同类常见区间之外；
2. 哪些分类的价格样本太少，不适合被读成价格指导；
3. 哪些分类的四分位区间宽到说明“分类”本身已经不是可比单位。

如果只把详情页函数逐件调用一遍，运营看板会为每件商品再查一次市场样本，样本口径也要靠人记忆保持一致。因此需要一条分类级聚合读路径：一次回答哪些分类值得人工看，而不是替每件商品重新生成一段文案。

## 目标

新增一个只读运营面板，按分类聚合出售商品的当前价格参考：

- 样本中位数、四分位区间、样本量与样本范围；
- 当前在售商品落在区间下方、区间内、区间上方的数量；
- 样本不足、区间退化后放宽、区间过宽三种边界状态；
- 按需要处理的在售商品数排序，让运营先看最集中的分类，而不是价格最高的分类。

面板不输出商品标题、卖家姓名或用户标识，也不生成自动调价任务。

## 样本口径

统计样本沿用详情页价格参考的既有边界，避免同一个项目里出现两套“同类价格”：

- `trade_mode = sale`；
- `price > 0`；
- `status in available / reserved / sold`；
- 优先取近 180 天商品；
- 近期没有样本时回退到历史样本；
- 每个分类最多取 500 件，按发布时间倒序，防止一个异常大的历史分类拖垮看板。

`reserved` 与 `sold` 可以参与“同类商品大概多少钱”，但不参与当前运营动作计数。它们不是当前需要处理的供给。

## 当前在售口径

区间外计数只看**当前真正可操作的供给**：

- `status = available`；
- 未过 `expires_at`；
- `trade_mode = sale`；
- `price > 0`。

已预订和已售出商品可能构成价格证据，却不能被运营提示“考虑调整”。把两者混进区间外计数，会把已经结束的供给读成当前问题。

## 区间与可信度

- 中位数与 P25/P75 使用与 `price_insights` 一致的插值口径，金额保留两位；
- 当 P25 与 P75 相等时，按中位数上下 10% 放宽，并明确标记“区间已放宽”，不把退化样本伪装成真实分布；
- 样本少于 3 件标为低可信，3—7 件标为中可信，8 件及以上标为高可信，沿用详情页阈值；
- 低于 3 件时仍展示中位数和区间，但不给区间外占比，只给数量；
- 区间宽度用 `(P75-P25)/中位数` 表示，超过 80% 标为“区间过宽”。这只说明分类内价格差异大，可能来自成色、配件或品类混杂，不自动说明卖家定价错误。

## 排序与提示

默认排序为：

1. 当前在售且落在区间外的商品数 从高到低；
2. 分类名 ascending。

上方计数与下方计数分开报。高于区间常见说明“可能影响成交意愿”，低于区间常见只说明“价格竞争较充分”，两者不应合成一个“异常率”。所有提示都写成观察，不写成因结论，更不触发通知或改价。

## 边界

- 看板 URL 的 `days` 参数不筛选本面板：它读的是当前价格快照，不是周期事件；页面上明确写清这一点；
- 不新增表、字段、迁移或缓存；
- 不修改 `Item.price`、不生成通知、不把结果写回商品；
- 不复用详情页函数逐件循环，避免分类面板引入 N+1 查询；
- 不展示商品、卖家或搜索词，导出 CSV 保持分类级汇总；
- 不把“高于区间”读成卖贵了，也不把“低于区间”读成应该涨价；成色和配件信息不在本面板的可比口径里。

## 验收

- 分类样本、中位数与四分位区间与详情页价格参考的边界一致；
- 当前在售的区间外计数不包含已预订、已售出、已过期、免费赠送或零价格商品；
- 近期无样本的分类回退历史样本并标记范围；
- 样本不足时只报数量，不给占比；
- P25=P75 时区间按 10% 放宽并显式标记；
- 排序优先暴露区间外当前在售最多的分类；
- 运营页面与 CSV 导出都有同一套分类级口径；
- 构建过程不写任何业务表。
