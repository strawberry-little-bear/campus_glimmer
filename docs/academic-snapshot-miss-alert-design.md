# 学期阶段快照缺行告警

## 起点

上一轮已经让 `AcademicTermSnapshot` 从「只被写」变成「真的被读」：`build_academic_calendar` 对已结束且区间完全匹配的阶段读快照，对进行中的阶段实时算。读路径打通后，路线图里留下的问题变成了正确性问题：**一个已结束阶段如果没有匹配快照，页面现在只是退回实时计算并把来源标成 `live`。**

数字仍然是对的，因为实时兜底会重新聚合四张业务表；但这会把一次真实的刷新中断、一次阶段配置调整后的匹配键失配、或者一次从未成功运行的快照命令，藏进「实时算」三个字里。对于使用者来说，实时行有两种完全不同的含义：

1. 阶段还在进行中，实时算是设计要求；
2. 阶段已经结束，本该读封闭快照，却找不到那一行，只能实时兜底。

当前 `source` 汇总只有 `snapshot_row_total` 与 `live_row_total`，这两种情况被合并在第二个数字里。这个问题不改变数值，却降低故障可见性，值得单独补一轮观测。

## 目标

把 `live` 再拆开，并让缺行在页面上变成明确提示：

- **快照行**：阶段已结束，且 `(phase_key, start_date, end_date)` 与当前阶段完全匹配；
- **进行中实时行**：阶段尚未结束，快照最多是上周的，实时算是既定策略；
- **缺行兜底**：阶段已结束，快照表里找不到这个阶段的任何行；
- **区间失配兜底**：阶段已结束，同阶段键下有旧行，但区间与当前配置不一致，不能读。

汇总处继续提供原有 `live_row_total`，同时新增 `running_live_row_total`、`fallback_live_row_total`、`closed_row_total`、`closed_snapshot_share` 与 `has_snapshot_miss`。只要 `fallback_live_row_total > 0`，面板顶部出现一条明确告警，指出有几个已结束阶段没有读到匹配快照、当前是实时兜底，并提示核对 `sync_academic_calendar` 与阶段边界。

## 逐行口径

每条阶段行保留现有 `source: snapshot/live`，避免已有模板、CSV 和测试失去稳定契约；新增 `source_reason`：

- `snapshot_closed`：读封闭快照；
- `running_live`：阶段进行中或未开始，实时算；
- `missing_snapshot`：阶段已结束且没有同阶段快照行；
- `range_mismatch`：阶段已结束且存在同阶段旧行，但区间不一致。

`source_note` 同步改成人能直接读懂的句子。缺行兜底不伪装成正常实时策略，也不把原因猜死：可能是命令从未跑过、阶段刚配置、命令中断或阶段边界被改过。页面只说明「没读到匹配行」，把判断留给运营。

## 告警边界

- 分母只算**已结束阶段**：`snapshot + fallback`。进行中阶段不是快照缺口，不能拿它稀释告警。
- `closed_snapshot_share` 为 `None` 表示没有已结束阶段，不报 0%。
- 只统计本次 `build_academic_calendar(limit_terms=3)` 实际渲染的启用学期；不把未启用学期、历史学期或未渲染阶段算进来。
- 不使用 `refreshed_at` 判断缺行。上一轮已经查证它是无条件推进的写入时间，回答不了内容是否可用。
- 不读任务台账来推断缺行原因，也不自动补刷、不删孤儿行、不改阶段边界。
- 不新增字段、约束、迁移或缓存层；本轮只细分已有返回结构、页面与导出。

## 页面与导出

面板顶部保留原有来源汇总，同时在存在兜底行时显示告警句。CSV 在来源说明后追加更明确的缺行说明，逐行导出继续使用 `source_note`，保证屏幕与下载件读到同一件事。

## 验收

- 已结束阶段缺行时：行 `source_reason=missing_snapshot`，汇总计入 fallback，页面出现告警；
- 同阶段旧行区间不匹配时：计为 `range_mismatch`，不读取旧行；
- 进行中阶段：计为 `running_live`，不触发缺行告警；
- 匹配快照存在：计为 snapshot，已结束快照占比正常；
- 无学期、无已结束阶段时不伪造 0%；
- 页面与 CSV 均能读到新增口径；
- 不写任何快照、阶段、学期或台账表。
