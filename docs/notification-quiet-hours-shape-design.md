# 免打扰时段的形状：两个时间字段第一次被数字读到

## 起点

`NotificationPreference` 上挂着三个和免打扰有关的字段：

- `quiet_hours_enabled` —— 免打扰总闸，默认关。
- `quiet_hours_start` —— 免打扰开始时间，默认 22:00。
- `quiet_hours_end` —— 免打扰结束时间，默认 08:00。

读取路径只有一处：`notifications.py` 的 `quiet_hours_active`。它先看总闸，再看当前本地时间是否落在
`start <= current < end` 里；当 `start > end` 时按跨午夜处理，例如 22:00–08:00。**免打扰只压顶部未读
角标，通知本身照常入库，通知中心里仍然可以打开**——这是产品语义，也是本模块不能把「免打扰」读成
「通知被丢弃」的原因。

写入路径是偏好表单。表单校验只拦一件事：总闸开着且开始时间等于结束时间时拒绝提交，提示至少保留
一个小时的可用时段。模型层没有这条约束，数据库里理论上可能出现相等的时间。

## 为什么这是真缺口

运营侧已有的读者是 `notification_preference_usage`。它把 `quiet_hours_enabled` 当成第 26 个开关单独
报：多少人开了、多少人没开、多少用户连偏好行都没有。**但 `quiet_hours_start` 与 `quiet_hours_end`
一次都没有被任何一个数字读过。**

于是四个具体的问题答不上来：

1. **开启免打扰的人，把窗口配在了什么时候。** 全部照抄默认的 22:00–08:00，还是各自改成了午休、
   晚自习、凌晨？这决定了默认值到底合不合身。
2. **窗口有多长。** 一个一小时的小窗口和一个二十三小时的大窗口，在「用户实际看不见多少角标」上是
   两件完全不同的事；只报开启率会把它们读成同一个数。
3. **一天里每个小时有多少人的角标正被压着。** 两个各十二小时的窗口可以错开成全天覆盖，也可以
   完全重叠成半天；逐小时叠加才能看出峰值落在几点。
4. **有多少人配了窗口却没开总闸。** 时间字段有默认值，即使用户不开免打扰也会存着 22:00–08:00。
   「改成过非默认窗口但总闸关着」是一批沉默的配置——他们碰过这个功能，却没有真正用上它。

这些全是快照问题，不是周期问题。偏好没有历史表，`updated_at` 在任何一次保存上都会刷新，改别的
开关也会动它，拿它反推「什么时候配的免打扰」是把噪声当信号。

## 报什么

### 一、总闸与配置的形状

按偏好行报四个数：

- 偏好行总数；
- 免打扰开启数与开启率（分母是偏好行，不是全体用户）；
- 开启且照抄默认窗口（22:00–08:00）的数量；
- 总闸关着但窗口已经是非默认值的数量。

没有偏好行的用户单独数，不并入「关着」：`quiet_hours_active` 对没有偏好行的人返回关，但「从没
碰过设置页」和「碰过、最后关掉」不是同一群人。这是 `notification_preference_usage` 已经定下的
口径，本模块沿用，两块面板可以并排读。

### 二、窗口方向与时长

只对**总闸开启**的偏好行报：

- 同日窗口（start < end）与跨午夜窗口（start > end）各自的数量与占比；
- 按固定档报窗口时长：1 小时内、1-4 小时、4-8 小时、8-12 小时、12-18 小时、18-23 小时。
  档位取产品语义的原值，不取分位数；
- 开始小时与结束小时各按 0–23 全列，0 样本小时也留在表里。

`start == end` 的行不进方向、时长和小时叠加，单独报成一个数据质量数：表单挡住了这条路径，但模型
层没有约束；而 `quiet_hours_active` 对相等时间的实际行为是全天返回真，等价于把角标压 24 小时。
非 0 就是绕过了表单，是一个待修的 bug，不是一档正常的分布。

### 三、逐小时叠加

把每个开启免打扰的窗口映射到 1440 个分钟格子上，再按小时聚合：

- 每个小时报「这一小时内平均有多少人的角标正被压着」（60 个分钟值的平均）与「这一小时内的
  峰值人数」；
- 24 个小时全列，包括 0 样本小时；
- 另报全天的峰值人数与它第一次出现的分钟。

用分钟格子而不是只比小时数字，是因为 22:30–08:30 和 22:00–08:30 在小时表上只差一格，实际相差
30 分钟；跨午夜窗口尤其不能用简单的数组切片。

## 口径上的取舍

- **快照口径，不按周期切。** `days` 参数只为了和看板其余面板保持一致而收下，不参与任何过滤。
- **分母是偏好行，不是全体用户。** 没有偏好行的用户单列，不摊进任何比例。
- **开启组的窗口形状只报开启组。** 总闸关着的行即使存着时间，也不进时长与逐小时叠加——那些
  时间此刻不生效，把它们叠进去会把「配过但没用」读成「正在压角标」。
- **非默认窗口的判定只看两个时间值，不看 `updated_at`。** 默认值就是模型里的 22:00 与 08:00；
  `updated_at` 被同一张表单里的所有开关共用，不能当「改过免打扰」的证据。
- **方向阈值沿用全站口径：一组至少 12 行才给方向，差值小于 8 个百分点视为噪声。**
- **分子为 0、分母存在时报 0.0；空分母报 None / 「—」，不报 0。**

## 不做什么

- 不改 `quiet_hours_active` 的跨午夜逻辑，不加模型约束，不加迁移。
- 不自动开总闸、不替任何人缩短窗口、不把非默认配置标成异常。
- 不报「免打扰之后未读提醒少了多少」：免打扰只压角标，通知照常入库，库里没有「角标本来会显示
  但被压掉」的记录，这个效果不可观测，不编。
- 不报窗口修改次数、修改时刻或配置存活时长：没有历史表，`updated_at` 不能当这个数用。
- 不按用户排名、不输出用户名、不列任何人的具体窗口。免打扰时段本身能暴露作息，聚合到小时和
  分钟格子是它能被运营读的最低粒度。
- 不读 `Notification` 表：本模块报的是偏好形状，不是通知效果。
- 不判断「窗口配得对不对」。有人只想要午休一小时安静，有人想整晚不见角标，都是合理选择。
