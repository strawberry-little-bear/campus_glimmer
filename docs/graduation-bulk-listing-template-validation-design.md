# 批量发布 XLSX 模板输入约束设计

## 要解决的问题

第六刀已经把批量发布导入模板做成服务端即时生成：CSV 只有一行固定表头，XLSX 冻结首行并提供交易方式下拉。它解决的是“表头从哪里来”和“文件长什么样”的问题，但卖家真正容易输错的并不是表头，而是行内字段：

- 标题超过 200 字符；
- 价格或押金填成负数、天价或普通文本；
- 借用天数填成 0、91 或小数；
- 成色超过模型 `max_length=100`。

这些错误目前都要等上传后由服务端解析器返回。服务端校验仍然是必须保留的最终边界，但如果 XLSX 模板能在输入时给出常见的范围提示，卖家就能少跑一轮“下载 → 填写 → 上传 → 报错 → 修改 → 再上传”。

## 目标

- 只增强 XLSX 模板；CSV 保持一行固定表头，不追加任何元数据或说明行。
- 继续由 `bulk_listing_template.py` 在内存中生成模板，不新增静态文件。
- 在 `A2:A21`、`C2:C21`、`D2:D21`、`E2:E21`、`F2:F21`、`G2:G21` 加入数据验证：
  - 标题：文本长度 1–200，允许留空；
  - 交易方式：出售 / 免费赠送 / 限期借用；
  - 价格：0–99,999,999.99 的数字，允许留空；
  - 押金：0–99,999,999.99 的数字，允许留空；
  - 借用天数：1–90 的整数，允许留空；
  - 成色：文本长度 1–100，允许留空。
- 每条验证提供中文错误标题和错误说明，只提示本列自己的约束。
- 不验证表头行，不改变七列顺序、列宽、冻结行和单一工作表结构。

“允许留空”是刻意设计：模板最多有 20 个商品行，但卖家可以只填 3 行；空行应由现有解析器的“非空商品”规则处理，不能被模板强制成 20 行全填。

## 明确不做

- 不在 XLSX 中写单元格公式、宏、隐藏工作表或第二个说明页。
- 不用公式表达跨列规则。“出售时价格必填”依赖同一行交易方式，Excel 数据验证的跨列公式兼容性差且容易把边界藏起来；这条仍由服务端解析器和 Django 表单最终判断。
- 不验证金额最多两位小数。常见表格软件对自定义数字文本验证的支持不一致，为了一个次要格式规则牺牲模板兼容性不划算；上传后的解析器继续拦截。
- 不为描述列加长度限制。当前描述是数据库文本字段，服务端导入边界也没有设置最大长度；模板不应先于业务规则发明一个上限。
- 不把模板验证结果当成发布依据。被某些工具忽略或人为绕过的验证规则不影响安全边界。

## 验收口径

- 生成的 XLSX 仍然只有一个“商品导入”工作表、一行固定表头、冻结首行，且没有示例商品行。
- 工作簿包含六组数据验证，覆盖第 2–21 行；交易方式下拉保持原语义。
- 每组验证的范围、错误标题和错误说明可被 `openpyxl` 读回并断言。
- 空模板回读仍然进入现有“至少需要一行非空商品”错误，而不是变成文件错误。
- CSV 模板字节内容保持不变。
- 服务端解析与批量发布测试不因模板元数据改变而失效。
