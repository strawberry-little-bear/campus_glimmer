# 毕业季批量发布：CSV 导入预览

## 起点

批量发布第一刀已经把“共同设置 + 最多 20 行商品”的服务端形状立住：所有行先校验，任何一个错误都会让整批不写入，成功时在一个事务内创建商品。它解决的是重复打开二十次发布页的问题，但毕业生手里更常见的原始材料往往是一张已经整理好的表。

第二刀只补这条链路的前半段：把 UTF-8 CSV 解析成待确认的商品行，先预览、再走原有批量发布校验。它不是后台导入任务，也不是 Excel 支持。

## 产品形状

### 上传与解析

批量发布页增加“从 CSV 导入”区域。卖家上传文件后，服务端只做解析和结构校验，不创建商品、不发通知、不写任何业务表。

CSV 的第一行必须是固定表头：

```text
标题,描述,交易方式,价格,押金,借用天数,成色
```

表头顺序必须一致，允许带 UTF-8 BOM 和首尾空白。数据行里完全空的行忽略；有效行超过 20 行时停止接收并给出明确错误。

### 预览

解析通过后跳回批量发布页，并进入预览态：

- 顶部显示本次解析出的非空行数和“还没有发布”的提醒。
- 原有商品行表单填入 CSV 数据，卖家可以直接修正任何一格。
- 共同设置仍由页面上的本批次表单提供，CSV 不携带分类、地点、专题和展示截止时间。
- 卖家点击原有“确认发布”按钮后，才进入第一刀已有的完整校验与事务写入。

解析失败时不进入半成品状态：页面显示文件级错误（例如表头不符、编码错误、文件过大）和行级错误（第几行哪一列缺什么或格式不对），卖家修正文件后重新上传。

## 服务端状态与一致性

上传解析后的行草稿放在当前登录用户的 session 中，并附带一次性 token：

- token 只用于找回本次预览，防止旧标签页拿到后来再次上传的新草稿。
- 每个用户同时只保留最新一份 CSV 草稿，重复上传即覆盖。
- 草稿有行数与字段长度上限，session 不保存上传文件本身。
- session 过期或 token 失效时，提示重新上传，不回退到来历不明的行数据。

预览页的表单提交仍以页面上的字段为准。CSV 解析结果只是初始值，不是写入凭证；最终发布必须重新经过 `BulkListingSettingsForm`、`BulkListingRowForm`、批次标题去重、20 行边界和事务写入。

## 校验分层

CSV 导入分三层，避免把所有错误都堆给最后发布按钮：

1. **文件层**：登录状态、文件存在、大小上限、UTF-8 解码、表头一致、行列形状。
2. **行层**：标题、描述、成色必填；交易方式必须是出售、免费赠送或限期借用；价格、押金、借用天数必须是可理解的数字；行号和列名随错误展示。
3. **发布层**：沿用现有批量发布校验，包括共同设置、同批次标题去重、免费 / 借用价格归零、借用默认值和全成或全不写。

行层校验允许把可恢复的值带回表单让卖家修正；文件层错误不生成预览。

## 隐私与滥用边界

- 导入入口与批量发布页使用同一登录保护，商品归属始终来自当前用户。
- 上传文件名、原始 CSV 和解析日志不落库。
- 不提供导入排行榜，不把导入规模用于卖家信用或标签。
- 20 行上限同时约束手工输入和 CSV 导入，超过上限必须分批。
- CSV 中的公式按普通文本处理，页面输出继续使用 Django 模板转义；不执行、不改写、不下载远端内容。

## 明确不做的事

- 不做 Excel / xlsx / 编码自动识别：先验证 UTF-8 CSV 的错误边界。
- 不做异步任务和导入历史：当前规模在请求内即可完成。
- 不做列映射配置：固定表头降低第一版歧义。
- 不做批量图片上传：CSV 只承载商品事实，图片仍走单件编辑。
- 不做“跳过错误行继续导入”：那会破坏第一刀的全成或全不写承诺。

## 验收口径

- 登录卖家能上传带 BOM 的 UTF-8 CSV，并在预览态看到最多 20 行已填商品。
- 上传、解析和预览全程不新增商品、不触发匹配通知。
- 表头错误、编码错误、超限、第 N 行第 M 列格式错误都有服务端测试。
- 预览后修改任意字段再提交，仍走原有批量发布事务测试。
- token 失效或 session 过期时只提示重新上传，不创建商品。
- 匿名访问导入与预览地址被登录保护拦截。
