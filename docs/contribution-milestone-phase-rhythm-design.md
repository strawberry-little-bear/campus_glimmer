# 贡献里程碑阶段节奏设计

状态：已落地
实现模块：`listings/contribution_milestone_phase_rhythm.py`、`listings/views.py`、`templates/listings/operations_dashboard.html`
前置能力：贡献里程碑事件台账、贡献里程碑覆盖审计

## 1. 要回答的问题

贡献里程碑覆盖审计已经能回答「事实台账和贡献流水能不能对上」。下一步才允许问：

> 同一个里程碑在同类学期的同一阶段里，达成强度是变快、变慢，还是只是阶段天数不同？

这个问题不能拿相邻两个任意周期直接相减。开学周的互助集中、考试周的行为结构、毕业季的供给释放都是校园季节性的一部分。把九月和十一月直接比较，得到的是季节，不是节奏。

## 2. 前置门槛

阶段节奏面板继续只读，并且先复用 `build_contribution_milestone_coverage` 的审计结果：

- 缺失事件大于 0 时，不输出任何节奏方向；
- 多余事件大于 0 时，不输出任何节奏方向；
- 事实不一致大于 0 时，不输出任何节奏方向；
- 规则快照差异不阻断，因为事件保存的是达成当时的规则解释。

门槛不通过时，面板只说明审计阻塞原因，不给「变快 / 变慢 / 持平」。这样不会把台账缺口读成用户行为变化。

## 3. 对照口径

- 事件按 `ContributionMilestoneEvent.reached_at` 的本地日期归入学期阶段；
- 只读取启用状态、完整落在固定回看期内的学期；
- 只比较已经结束的阶段，进行中的阶段没有封闭分母；
- 对照键是：同一 `phase`、同一 `term.kind`、最新两个匹配学期；
- 里程碑对照同时要求 `milestone_type` 与 `milestone_code` 一致；
- 每个格子输出事件数、覆盖用户数、阶段天数和每百天事件强度；
- 方向只看每百天强度，不直接比较裸事件数，因为阶段长度可以不同；
- 两侧事件数都达到最小样本门槛才给方向，薄样本只报数字；
- 事件落在没有学期、学期内未划分阶段或回看期之外时单独计数，不摊派进可比格子。

固定回看期取 420 天，用于容纳同类学期的最近两次出现。运营看板的 `days` 参数仅作为注册表兼容传入，不切本面板。

## 4. 隐私与动作边界

- 不输出用户名、贡献标题、描述、来源幂等键或触发贡献明细；
- 覆盖用户数只作为样本量说明，不用于排名；
- 不发通知、不触发庆祝、不改等级或徽章、不改贡献流水和事件台账；
- 不把节奏变慢解读为用户不活跃：贡献积分来自特定互助行为，交易活跃不等于贡献里程碑密集；
- 面板不自动调整积分规则、徽章门槛或运营策略。

## 5. 验收口径

- 覆盖审计干净时，生成同类学期同阶段的最新两次对照；
- 缺失、多余或事实不一致会阻断方向输出；
- 规则快照差异不阻断；
- 进行中的阶段不参与方向判断；
- 阶段长度不同的事件数用每百天强度比较；
- 任一侧低于最小样本时只显示数字；
- 无同类上一学期、事件未落入阶段等情况有明确状态；
- 页面与 CSV 共用同一构建器，且均保持只读和聚合输出。

## 6. 落地记录

- 构建器落在 `listings/contribution_milestone_phase_rhythm.py`，页面与 CSV 共用同一份结果；
- 面板注册进运营看板共享构建器，不新增表、迁移或写入路径；
- 验证覆盖同类学期同阶段对照、每百天强度、覆盖审计阻塞、快照差异放行、薄样本、进行中与无学期事件，以及页面 / CSV 只读契约。
