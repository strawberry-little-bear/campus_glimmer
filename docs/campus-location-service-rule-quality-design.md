# 校园开放规则配置审计设计

## 要解决的问题

校园地点的每周开放时段与单日例外已经进入推荐和预约提醒，交付开放时段风险审计也会回头看未来安排。但规则本身仍然只能逐条翻后台：一个替换例外没有配置任何时段、多条替换时段互相重叠、跨午夜时段被次日例外截断、启用地点没有任何启用每周时段，这些配置形状没有一个集中解释处。

它们都不是数据库错误，也不一定需要修改；有些是刻意协商出来的结果。问题在于维护者看不到“这份规则实际会怎么被解释”。本轮补一个只读配置审计面板，把规则形状、例外生命周期和需要人工确认的配置放在一起。

## 目标

- 统计启用与停用地点、启用地点中的已登记与未登记每周时段、启用与停用每周时段。
- 统计跨午夜时段、互相重叠或相邻的每周时段组合，以及启用单日例外的过去 / 今天 / 未来生命周期。
- 单独识别五类配置信号：

  - 启用地点没有任何启用每周时段；
  - 启用例外挂在停用地点上；
  - 替换例外没有配置任何当天时段；
  - 同一替换例外的多条时段互相重叠；
  - 跨午夜每周时段会被次日启用例外截断。

- 提供地点聚合视图，展示每周规则数、例外数和配置信号数。
- 提供最多 20 条的人工核对清单；CSV 导出完整清单。
- 页面与 CSV 共用同一个构建器，所有数字和清单保持同构。
- 保持只读，不修改地点、时段、例外或任何业务记录。

## 判断口径

- 审计对象是地点、每周时段与单日例外的当前配置，不读取订单、预约、搜索或用户行为。
- “未登记每周时段”指启用地点没有启用 `CampusLocationServiceWindow`；停用时段不计入登记，也不把未登记写成错误。
- 替换例外没有任何 `CampusLocationServiceExceptionWindow` 时，评估结果等价于当天关闭；本面板把它列为“替换但无时段”，要求维护者确认这是不是想表达的含义。
- 替换时段按开始时间排序后两两相交即重叠。评估器会合并重叠区间，所以这不是功能故障，只是维护复杂度信号。
- 每周时段结束时间不晚于开始时间即视为跨午夜。若次日存在启用例外，当前统一评估器会把前一时段截断到午夜；本面板只提示这个解释边界，不改规则。
- 例外的生命周期按构建时刻的本地日期划分：过去、今天、未来。启用中的历史例外不算垃圾数据，因为它们仍可解释历史安排。
- 一个地点可以同时命中多个配置信号；本面板刻意不互斥拆分，聚合行会用“信号数”而不是“异常地点数”表达这一点。
- 清单按地点名、生效日期、信号优先级和规则文本排序，避免同分漂移。
- 看板顶部的统计周期参数不改变本面板口径。

## 页面与导出

- 运营看板新增“校园开放规则配置审计”面板：

  - 顶部摘要展示启用地点、已登记地点、启用每周时段、跨午夜时段和启用例外；
  - 中部列出地点聚合，不输出用户或交易信息；
  - 底部列出配置核对清单，页面最多 20 条；
  - 边界说明强调“重叠和未登记可以是刻意选择，本面板只解释配置形状”。

- CSV 导出新增同名节，输出摘要、地点聚合和完整核对清单。
- 导出与页面共用同一构建器；页面截断只影响展示，不影响汇总。

## 明确不做

- 不自动合并重叠时段、补齐替换时段、关闭历史例外或修改地点状态。
- 不把未登记时段、重叠时段或跨午夜截断判定为配置错误。
- 不接入门禁、课表或实时开放状态。
- 不按用户、订单或预约解释配置，不输出任何交易隐私。
- 不给地点配置打综合分，不自动进入维护队列或触发通知。
- 不把结果写回地点、时段、例外或运营任务。

## 验收口径

- 无配置时输出稳定空态，不把 0 报成异常。
- 启用地点未登记、停用地点例外、替换无时段、替换时段重叠、跨午夜被次日例外截断可区分。
- 过去 / 今天 / 未来例外按本地日期归期，跨时区测试时刻不改变口径。
- 页面最多 20 条，CSV 输出完整清单。
- 页面标题与 CSV 节标题同名，页面与 CSV 的核心语言一致。
- 构建器重复执行不写任何业务表，结果稳定。
- 既有每周时段、单日例外、交付开放时段风险和运营看板测试保持通过。
