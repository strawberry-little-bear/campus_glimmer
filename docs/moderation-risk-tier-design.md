# 内容审核风险分级设计

## 要解决的问题

内容审核现在只有一套 0–100 分和 low / medium / high 三档等级。分数能表达「命中了多少规则」，但不能表达「运营应该以什么节奏复核」：一条只命中外部链接的 20 分记录，和一条命中私下转账、刷单或裸聊的 50 分记录，都会进入同一个待复核队列，再按分数混在一起。

这轮迭代补的是审核规则的处理分级：

- 把规则本身分为「严重风险」「脱离平台联系」「低权重线索」三档；
- 拦截时把最高档写入 `ModerationEvent.risk_tier`；
- 审核队列按分级给出复核节奏和超时提示；
- 保留现有分数与风险等级，作为规则解释和历史兼容口径。

分级只影响人工查看顺序与提醒节奏，不自动确认违规，也不自动放行。

## 分级口径

### critical：严重风险，4 小时内复核

命中「高风险交易」规则：押金、预付款、私下转账、刷单、博彩、裸聊。

这一类直接指向资金、赌博、色情或欺诈场景。即使单条规则只有 50 分，它也不应该和普通外链使用同一等待预期。

### elevated：脱离平台联系，12 小时内复核

命中「微信导流」或「手机号」规则。

这一类可能只是同学之间交换联系方式，也可能是导流或诈骗前置动作。它需要人工判断语境，因此不直接自动处置，但应比普通外链更早被看见。

### caution：低权重线索，48 小时内复核

命中「外部链接」规则。

课程资料、二手平台页面和商品介绍都可能包含正常链接。它是需要人工看一眼的线索，不是高优先级风险。当前规则不做链接白名单，避免把“域名看起来可信”误当成安全判断。

多条规则同时命中时取最高档：`critical > elevated > caution`。分数仍按原权重累加并封顶 100，`risk_level` 仍由分数阈值推导，二者不互相覆盖。

## 数据与历史处理

- `ModerationEvent` 新增 `risk_tier`：
  - `critical`：严重风险；
  - `elevated`：脱离平台联系；
  - `caution`：低权重线索。
- 新事件在拦截时写入最高命中档，不事后重算，避免未来规则调整改写历史事实。
- 历史记录按 `matched_terms` 中的既有规则标签回填：
  - 命中“高风险交易”补 `critical`；
  - 否则命中“微信导流”或“手机号”补 `elevated`；
  - 其余补 `caution`。
- 无法识别的历史标签不猜成因，统一归入 `caution`，仍保留原 `risk_score` 与 `risk_level` 供人工判断。
- Django Admin 展示并支持按分级筛选，但分级字段与复核材料一样只读，避免后台手改破坏拦截事实。

## 队列展示

- 待复核队列先按 `critical → elevated → caution` 分组，同档内继续按风险分数和拦截时间排序。
- 已确认 / 已放行记录排在待复核之后，保留分级标签用于复盘。
- 队列提供分级筛选，并显示三档待复核数量。
- 待复核行展示对应目标：4 小时 / 12 小时 / 48 小时；超过目标显示“已超时”，进入最后 25% 观察窗显示“即将超时”。
- 分级标签与命中规则同时展示，管理员能看到“为什么这一条被归入这一档”。
- 缺恢复材料、误判未恢复等既有提示优先级高于节奏提示，避免一条内容已经无法恢复时仍被读成普通时效问题。

## 只读与安全边界

- 不根据分级自动确认、自动放行或自动通知用户。
- 不自动封禁作者，不生成作者榜，不把分级写回用户资料。
- 不读取内容正文以外的新信息；正文仍只在人工复核和既有搜索中可见。
- 目标时间是运营节奏，不是对外承诺的 SLA，也不进入用户通知文案。
- 分级不是违规结论；最终状态仍由管理员复核后写入。
- 不做敏感词管理后台和运营热更新。规则仍随代码发布，保证每次变化可测试、可回滚。

## 非目标

- 不引入机器学习分类器或外部内容安全服务。
- 不做链接白名单、域名信誉评分或自动访问外链。
- 不做申诉流程；申诉仍留作独立迭代。
- 不改既有 `moderation_rule_quality` 的误判率、漏判率和复核时效口径；后续可在该面板上增加按分级的拆分。
- 不把 4 / 12 / 48 小时目标接入自动升级或自动提醒轰炸。

## 验收

- 规则分析能返回命中的最高分级，且分数与风险等级保持既有行为。
- 新拦截事件持久化 `risk_tier`。
- 历史事件按命中规则回填，未知标签不伪装成高风险。
- 审核队列能按分级筛选，待复核排序为 `critical → elevated → caution`。
- 三档待复核数量、目标时间、即将超时和已超时提示正确。
- Django Admin 只读展示分级并支持筛选。
- 数据库迁移、系统检查、迁移检查和相关审核测试通过。
