# 校园专题分阶段复盘设计

状态：已落地
实现模块：`listings/campaign_phase_review.py`
测试模块：`listings/test_campaign_phase_review.py`
页面与导出：运营看板“校园专题分阶段复盘”面板及同名 CSV 节
前置能力：校园专题表现

## 1. 要回答的问题

现有 `build_campaign_analytics` 会把专题窗口与看板统计周期重叠的部分合在一起看，适合回答「这个专题最近带来了多少供给、曝光和预约」。但它看不到专题自己的时间结构：

> 商品是在开场集中补进来的，还是直到收尾才补上？
>
> 预约是在前段形成热度，还是主要发生在临近结束时？
>
> 完成交易是否集中在中段，后段是否出现断档？

这些问题不能拿专题之间的裸总量直接回答。一个持续 60 天的专题和一个持续 14 天的活动，商品数相同也不代表节奏相同；一个只有 2 次预约的专题，把 3 段切成「强、弱、更强」也只是小样本上的抖动。

## 2. 统计范围

- 只读取 `ends_at <= now` 的已结束专题；未设置结束时间或仍在进行中的专题不参与阶段判断；
- 按 `ends_at` 倒序取最近 8 个已结束专题，避免看板每次请求无限回算历史活动；
- 每个专题完全按自己的 `starts_at` 到 `ends_at` 均分为前段、中段、后段，不跟随运营看板的 `days` 参数；
- 三段边界采用半开区间，避免恰落在边界上的记录被前后两段重复计数；
- 商品按 `Item.created_at` 归段，收藏按 `Favorite.created_at` 归段，预约按 `Order.created_at` 归段；
- 浏览沿用现有专题表现口径，以 `BrowsingHistory.last_viewed_at` 将浏览记录归段，不把 `view_count` 再展开；
- 完成交易按该阶段创建、当前状态为 `completed` 的订单统计，不伪造没有留存的完成时刻。

## 3. 每段输出

每段固定输出：

- 阶段起止时间与阶段天数；
- 新增商品；
- 浏览记录数；
- 收藏数；
- 预约数；
- 完成交易数；
- 浏览转预约率；
- 预约完成率；
- 预约每百天强度；
- 浏览每百天强度；
- 新增商品每百天强度。

页面按专题展示三段对照，CSV 使用同一份结构化结果，不另写一套口径。

## 4. 方向与样本门槛

- 阶段节奏只在三段都已结束时计算，不根据进行中的尾巴猜测方向；
- 预约高峰只看每百天预约强度，不比较裸预约数，避免不等长阶段造成假差异；
- 只有前、中、后三段都至少有 3 次预约，才输出「前段 / 中段 / 后段预约强度最高」；
- 少于门槛、阶段无数据或三段完全相同时，只报数字并标记「样本不足 / 节奏均衡」，不强行给结论；
- 已结束专题少于 2 个时，不输出跨专题总结；
- 跨专题总结只统计有足够样本且能判出高峰的专题，分别列出前段、中段、后段各落在多少个专题，不做专题排名，也不把人数当成绩；
- 每百天强度是解释节奏的速率指标，不用于预测下一次活动，也不自动生成运营任务。

## 5. 隐私与动作边界

- 只输出专题级聚合，不输出用户名、商品标题、订单号或用户级行为路径；
- 不显示单个用户的浏览、收藏或预约明细，不尝试拼接跨专题个人轨迹；
- 不调整专题的投放位置、开关、起止时间、商品归属或曝光权重；
- 不自动结束、续期、复制或创建专题，不触发通知，不写入新的运营表；
- 浏览、收藏和预约只能说明业务记录的时间分布，不能证明某个阶段「更有效」或造成后续转化。

## 6. 验收口径

- 只统计已结束专题，进行中和无结束时间专题有明确忽略说明；
- 三段边界不重叠、不遗漏，专题总记录数与三段合计一致；
- 商品、浏览、收藏、预约和完成交易均按各自时间字段归段；
- 阶段长度不同或活动很短时仍使用每百天强度比较；
- 任一段预约不足 3 次时不输出高峰方向；
- 已结束专题少于 2 个时不输出跨专题总结；
- 页面与 CSV 共用同一构建器，并且都不新增表、不迁移、不产生写入；
- 运营看板仍可在原有统计周期下查看专题总漏斗，本面板只补充专题自身的三段复盘。
