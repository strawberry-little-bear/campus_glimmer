# 新商品搜索曝光冷启动

状态：设计稿（只读，不新增表和字段）
计划模块：`listings/search_exposure_cold_start.py`
数据源：`Item`、`SearchImpression`、`SearchClick`
计划面板：运营看板「新商品搜索曝光冷启动」

## 1. 要回答的问题

搜索位置面板已经能回答「同一页里前排和深位的点击率差多少」，配对质量面板也能回答「点击分子有没有可用的曝光分母」。它们共同缺一块更靠前的事实：

> 一件新发布的商品，要等多久才第一次进入搜索结果页？

这不是排序好坏，而是供给能否被搜索看见的冷启动问题。若大量商品发布后 72 小时仍没有任何搜索曝光，运营看到的「无结果搜索」可能不是没有供给，而是供给沉在列表之外；反之，若首曝很快但点击很少，问题更可能在标题、首图、价格或排序解释。

本面板只回答四件事：

1. 周期内有足够观察时间的新商品，多少拿到过搜索曝光；
2. 首次曝光距离发布用了多久；
3. 首次曝光之后有没有搜索点击；
4. 哪些分类的冷启动形状明显不同。

## 2. 队列与观察窗

- 队列只收统计周期内创建的 `Item`，不按当前在售状态剔除；商品可能很快卖出，但它发布后是否被搜索看见仍是有效事实。
- 为避免右删失，队列截止在 `now - 48 小时`。刚发布两小时的商品还没等到曝光，不能被算成「永远没曝光」。
- 首次曝光取该商品在发布时间之后、构建时刻之前最早的一条 `SearchImpression`。
- 首次点击取首次曝光之后最早的一条 `SearchClick`。点击若早于首次曝光，单独列为形状，不拼成转化。
- `SearchImpression.search_query` 为空仍可作为曝光事实；本面板问的是商品有没有出现在结果页，不是搜索归因质量。

## 3. 分桶与聚合

首曝延迟固定分为：

- 1 小时内；
- 1—6 小时；
- 6—24 小时；
- 1—3 天；
- 超过 3 天；
- 48 小时观察后仍无曝光。

延迟分位数只对已拿到首曝的商品计算，使用最近秩，不插值。分类聚合输出队列商品数、已首曝数、未首曝数、首曝后有点击数和首曝延迟中位数；样本不足时分位数留空。

清单按「未首曝优先，其次首曝更慢，再按更早发布」排序。页面最多列 20 条，CSV 导出完整清单。

## 4. 异常形状

以下形状只计数并列清单，不判成因：

- 曝光时间早于商品发布时间：不能生成负延迟；
- 点击早于商品首次曝光：可能是旧链接、手工 URL 或时间形状异常；
- 商品有点击但没有任何可用曝光：说明分子存在而分母缺失。

这些行不进入首曝延迟和点击率主统计，避免把数据形状读成搜索效果。

## 5. 隐私边界

- 不输出商品标题、描述、价格、卖家、搜索词或用户；
- 不按卖家、买家、搜索词排名；
- 清单只带商品 ID、分类、交易方式和状态标签；
- 页面与 CSV 共用同一个构建器，截断只影响展示，不影响汇总。

## 6. 明确不做

- 不新增表、字段、索引或迁移；
- 不修改搜索排序、商品刷新、发布流程或曝光写入；
- 不给商品打质量分，不自动置顶，不触发卖家提醒；
- 不把「未首曝」判定为商品问题；搜索量低、分类冷门和学期节奏都会造成同一形状；
- 不把首曝后的点击率解释成首图或标题因果效果。

## 7. 为什么先做只读看板

发布、搜索曝光和点击三条链路已经都有数据，但它们分别被供给面板、位置曲线和配对质量读取，缺少一个以「新商品队列」为主体的纵向视角。先量冷启动形状，可以判断后续应优化分类供给、搜索召回、卖家引导，还是只需要解释学期节奏；在证据出现前不调整排序。
