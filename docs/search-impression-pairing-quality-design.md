# 搜索曝光与点击的配对质量

状态：设计稿（只读，不新增表和字段）
计划模块：`listings/search_impression_pairing_quality.py`
数据源：`SearchImpression`、`SearchClick`、`SearchQuery`
计划面板：运营看板「搜索曝光与点击配对质量」

## 1. 要回答的问题

搜索侧现在有两条已经落库的事件流：

- `SearchImpression`：搜索结果页渲染一件商品时写一行，带 `search_query`、`item`、`user`、`position`；
- `SearchClick`：学生从带 `search_id` 的详情页链接进入时写一行，带同样的归因字段和点击位置。

`search_position_quality` 已经把两边的 `position` 读成位置衰减曲线和排序效果；搜索洞察页也用两边行数计算点击率。它们都有一个共同前提：**分子和分母是可以配对的同一批搜索事件。**

这个前提本身一直没有被检查。现有读法至少有三处静默丢弃：

1. `search_query` 为空的行会被关联查询排除；
2. `position = 0` 的行会被位置面板排除；
3. 点击表先于曝光表一个迁移上线，历史点击可能天然找不到曝光分母。

这些丢弃不一定错：`search_query` 是 `SET_NULL`，搜索记录被删除后，旧点击仍应保留；位置为 0 也可能是旧链接或手写参数。问题不是把它们删掉，而是**运营至少要知道这类行有多少，避免把数据完整度读成搜索效果**。

本模块只回答：

1. 周期内曝光和点击各有多少行；
2. 点击里有多少能找到同一搜索、同一商品、且不晚于点击的曝光；
3. 点击位置与当时曝光位置是否一致；
4. 缺搜索记录、零位置、无法配对、未来时间这些形状各有多少；
5. 成功配对的点击隔了多久才发生，旧链接或回访占多大形状。

## 2. 分析单位与周期

分析单位是一行点击或一行曝光，不是一次搜索。周期沿用运营看板的本地自然日边界：

```text
period_start <= created_at < now
```

未来时间单独计数，不进入主统计。搜索行为本身有昼夜和学期节律，把未来行并入周期会把异常当成流量。

点击配对不只看周期内曝光。只要点击发生在周期内，就允许它去找这张曝光表上线以来更早的同 `(search_query, item)` 曝光。学生保存了一个搜索结果链接，几天后再次打开，这是合法行为；把配对窗口截成 30 天会把这批点击错判成无分母。

## 3. 配对口径

一次点击可配对，当且仅当：

```text
SearchImpression.search_query_id = click.search_query_id
SearchImpression.item_id = click.item_id
SearchImpression.created_at <= click.created_at
```

不要求用户相同。链接可以被转发，登录状态也可能在看见与点击之间变化；把匿名曝光和登录点击判成异常，等于要求两次请求都来自同一个人，这超出当前模型能证明的范围。

不要求时间贴近。表里没有请求 ID 或渲染批次，只有事件时间。配对后再按延迟分桶，而不是先拍一个「几分钟内才算」的阈值把旧链接扔掉。

延迟从最早一条可配对曝光算起：它是这个链接第一次可以被生成的时间下界，比拿最近一次重复曝光当起点更不容易把很旧的链接读成新点击。

点击位置与该次点击配对到的任一历史曝光位置相同，记为位置一致。若同一 `(search_query, item)` 曾在多个页面以不同位置出现过，只要点击位置在历史位置集合内，就不算错位。这仍然不是完全精确的请求级配对，但它能发现位置参数被手工改动或旧口径漂移的规模。

## 4. 不可观察的边界

- **数不出曝光写入失败次数**：搜索页的 `bulk_create` 没有单独落业务失败记录，本模块只读已经落库的行。
- **不能证明「用户肉眼看到」**：曝光行只说明服务端渲染了这条结果。
- **不能区分历史点击、转发链接和异常写入**：点击表先于曝光表上线，早于最早曝光的点击天然无分母；当前库没有部署时间戳，只能以库内最早曝光时间作为观测边界。
- **不能把未配对读成作弊或 bug**：手写 URL、旧链接、搜索记录删除和数据迁移都会产生相同形状。
- **不重建搜索词**：`search_query` 为空时，不拿 `query` 字符串反推归属；该字段本来就在被删除的那张表里。

## 5. 输出形状

### 5.1 字段与结构

固定列出：

- 匿名或已注销访客：合法形状，不进缺失；
- 曝光缺搜索记录：影响搜索关联指标的分母；
- 点击缺搜索记录：影响点击分子；
- 点击位置为 0：位置面板读不到；
- 点击找不到更早的同搜索同商品曝光：单列，不判成因；
- 点击早于同搜索同商品的最早曝光：说明至少存在同组曝光，但点击不能归给它；
- 时间在未来：按曝光、点击分列，均不进主统计。

### 5.2 配对与延迟

- 可配对点击数、占比；
- 位置一致与不一致的点击数；
- 点击延迟按 `5 分钟内`、`5—60 分钟`、`1—24 小时`、`1—7 天`、`超过 7 天` 固定分桶；
- 空档不报 0%，报 `None`。

### 5.3 覆盖

只报曝光、点击各自有写入的自然日。搜索日志断日可能来自假期、低流量或无搜索，不判写入失败。

## 6. 隐私与安全边界

- 不输出搜索词、商品标题、用户名、卖家名或 URL；
- 不按用户、商品、搜索词、卖家排名；
- 不把高频搜索或高频点击当成风控信号；
- 异常只报数量，不报原始 key 或参数；
- 面板和 CSV 导出使用同一套聚合口径。

## 7. 不做什么

- 不新增表、字段、索引或迁移；
- 不改搜索页的 `bulk_create`，也不把它改成非致命写入；
- 不给历史点击回填曝光；
- 不修改 `search_position_quality` 的现有过滤规则；
- 不把配对结果写回排序、相关性反馈或搜索质量分；
- 不自动删除孤儿行或零位置行；
- 不用这个面板判断搜索效果好坏。

## 8. 为什么先做只读看板

搜索点击率已经是运营看板的核心指标之一，位置曲线也开始参与排序判断。若分母和分子的配对质量本身不可见，后续任何「点击率变低」「排序没起作用」的读数都可能把数据形状变化误读为产品变化。

先量形状，再决定是否需要写入请求 ID或调整外键策略；在证据出来之前，只读面板是最小且可回滚的一步。
