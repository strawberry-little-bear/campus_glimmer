# 批量发布导入错误摘要设计

## 要解决的问题

CSV 与 XLSX 导入现在会把行级错误逐条列在上传区：每条错误都能定位到第几行、哪一列，这是必须保留的可用性。但批量文件的问题常常是同一类错误反复出现：二十行里十几行都把“出售”写成“出出售”，或者一列金额普遍带了三位小数。当前页面把这些重复信息平铺展示，卖家要先在长列表里自己数规律，再逐行修改。

第八刀要解决的不是“发现更多错误”，而是把已经发现的错误读清楚：先告诉卖家一共有多少个错误、涉及多少行、最集中的问题是什么，再保留完整的逐条清单。

## 目标

- 新增一个纯内存摘要模块，输入现有 `BulkListingCsvRowError` 列表，输出给页面使用的摘要结构。
- 摘要包含：
  - 错误总数；
  - 涉及的行数；
  - 按「列 + 错误文案」聚合的问题组；
  - 每组出现次数、涉及行号和首次出现位置；
  - 页面展示前 6 组，以及被折叠的问题组数量。
- 问题组排序先按出现次数降序，再按首次出现行号、列名和文案稳定排序，避免同一份文件每次渲染出不同顺序。
- 同一行同一列同一文案只计入一次，行号列表保持首次出现顺序。
- 上传失败页面先显示摘要，再用折叠块保留全部原始行级错误；文件层错误继续单独展示，不混入行级摘要。
- CSV 与 XLSX 共用同一条摘要路径，因为两者已经共用行校验结果。

## 明确不做

- 不改解析器的错误文案、50 条错误上限或错误发现顺序。
- 不跳过错误行、不自动修正单元格、不生成修正后的文件。
- 不把导入错误写入数据库，不做导入历史、异步任务或跨用户统计。
- 不把摘要当成新的校验边界；最终发布仍由 Django 表单和批量发布事务重新校验。
- 不隐藏任何原始错误。摘要是阅读层，完整清单仍可在页面展开。
- 不给卖家生成信用、标签或运营排名；这是单次上传的即时可用性改进。

## 验收口径

- 摘要模块对空错误列表返回空结果，不渲染摘要区。
- 聚合、去重、排序、前 6 组截断和剩余组数有单元测试。
- 无列名错误（例如“这一行必须正好 7 列”）也能进入摘要，显示为整行问题。
- CSV 上传错误页渲染错误总数、涉及行数、问题组数量和最高频问题，并保留原始逐条错误。
- XLSX 走同一视图路径，不需要单独复制摘要逻辑。
- 成功导入预览、最终批量发布和空模板守卫行为不变。
- 摘要过程不读写数据库，不改变 session 草稿语义。
