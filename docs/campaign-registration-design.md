# 校园专题报名设计

状态：设计完成，待实现  
实现模块：`listings/campaign_registration.py`  
测试模块：`listings/test_campaign_registration.py`  
页面入口：专题详情、我的专题足迹、运营看板  
前置能力：校园专题、校园专题表现、校园专题分阶段复盘

## 1. 背景与问题

校园专题已经能把毕业季、教材交换周等短期活动组织成一个公开集合，也能让卖家把商品加入专题。但当前专题仍然只是“商品集合”：

- 浏览者只能看，不能明确表达“我想参与这个专题”；
- 运营只能看到商品、浏览、收藏和预约，无法知道有多少人主动关注活动；
- 用户离开页面后没有个人入口回看自己参加过的专题；
- 如果后续要做专题开市提醒、上新提醒或活动复盘，缺少一条可靠的参与事实。

本期补上专题报名，不改变商品交易链路。报名表示用户愿意关注并参与这个专题，不代表预约商品、锁定库存或承诺到场。

## 2. 目标与非目标

### 目标

1. 登录用户可以在进行中的专题里报名，也可以取消报名；
2. 重复点击、并发请求和重复提交不能让同一用户产生活跃报名记录；
3. 取消后再次报名时，保留之前的参与区间，而不是覆盖历史；
4. 专题公开页只展示报名人数，不展示参与者身份；
5. 用户有一个自己的专题足迹页面，能回看当前参与和历史参与；
6. 运营可以读到报名事实，但不会把报名误读成订单或成交；
7. 模型、服务、视图、模板和测试保持职责分离，便于后续接入通知和活动目标。

### 非目标

- 报名不锁定商品、不创建订单、不承诺库存；
- 不自动把报名用户加入私信、群聊或营销名单；
- 不在本期发送专题上新通知；
- 不公开报名名单、用户名、头像或用户级行为；
- 不根据报名人数自动调整专题排序、推荐权重或商品曝光；
- 不把报名数当成成交转化率的分子或分母。

## 3. 用户故事

### 浏览者

- 我进入一个正在进行的专题，能看到已有多少人报名；
- 我登录后可以点击“加入专题”，页面明确告诉我这是关注活动，不是预约商品；
- 我已经报名时，按钮变为“退出专题”，再次提交仍然安全；
- 我可以在“我的专题足迹”里看到自己加入过哪些专题，以及加入、退出时间。

### 专题运营者

- 我能在后台看到每个专题的活跃报名人数；
- 我能查到一条报名记录属于哪个专题和用户，但不会在公开页面暴露这些信息；
- 我能从运营看板看到统计周期内的新增报名和当前活跃报名，作为活动关注度指标；
- 我不能通过报名数据推断某个用户买了什么。

### 系统维护者

- 并发双击不会产生两条活跃报名；
- 重复退出不会报错或改写退出时间；
- 专题结束后，报名数据保留为历史事实，继续报名会被明确拒绝；
- 所有状态变化都有服务端校验与可重复的回归测试。

## 4. 数据模型

新增 `CampaignRegistration`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `campaign` | `ForeignKey(CampusCampaign)` | 所属专题，删除专题时级联删除参与记录 |
| `user` | `ForeignKey(User)` | 报名用户，删除用户时级联删除参与记录 |
| `joined_at` | `DateTimeField` | 本次加入时间 |
| `left_at` | `DateTimeField(null=True)` | 本次退出时间；活跃记录必须为空 |
| `is_active` | `BooleanField` | 当前是否仍处于该次参与区间 |
| `created_at` | `DateTimeField(auto_now_add)` | 记录首次写入时间，仅用于审计 |

关键约束：

- `(campaign, user)` 只允许存在一条 `is_active=True` 的记录；
- `is_active=True` 时 `left_at` 必须为空，`is_active=False` 时 `left_at` 必须非空；
- `(campaign, is_active, joined_at)` 和 `(user, is_active, joined_at)` 建立索引，分别服务公开计数和个人足迹查询。

这里采用“每次加入一条新记录、退出时关闭当前记录”的方式，而不是复用同一条报名行。这样 `joined_at / left_at` 本身就构成完整的参与区间，不需要额外的布尔字段去猜测历史。数据库的部分唯一约束负责兜住并发重复报名。

## 5. 状态与时间边界

专题报名只有两个业务状态：

```text
未报名 --加入--> 已报名 --退出--> 未报名
```

- 只有 `CampusCampaign.is_live(now)` 为真的专题可以加入或退出；
- 专题尚未开始、已经结束或已停用时，页面不提供操作，服务端也会拒绝；
- 专题进行中加入后，即使专题之后结束，已有记录仍然保留；
- 已结束专题的参与记录属于历史事实，本期不允许事后修改；
- 报名人数只统计 `is_active=True` 的记录；
- 每次加入创建新记录，因此重新加入不会被误算成“重复用户”，但公开人数始终使用当前活跃记录数；
- 用户级去重只用于防重复点击，不用于伪造“独立参与人数”指标。

## 6. 权限与隐私

- 加入和退出必须登录，并使用 `POST`；
- 用户只能操作自己的报名记录，不能通过请求参数指定其他用户；
- 公开专题列表和详情只显示聚合人数；
- 个人足迹页只显示当前登录用户自己的记录；
- 运营看板只显示专题级聚合，不显示报名用户名单；
- 后台管理员可以查询报名记录，用于运营维护和问题排查；
- 日志与错误提示不得包含密码、完整个人信息或用户级商品行为。

## 7. 页面与交互

### 专题列表

- 每个专题卡片显示当前活跃报名人数；
- 已登录用户可看到“我的专题足迹”入口；
- 报名数只是关注度指标，不改变原有商品排序。

### 专题详情

- 顶部信息区显示当前报名人数；
- 未登录用户看到登录后加入的提示；
- 已登录且未报名用户看到“加入专题”按钮；
- 已报名用户看到“已加入专题”状态和“退出专题”按钮；
- 按钮下方说明“加入表示关注专题，不会预约商品或占用库存”；
- 操作通过 POST 提交，并携带安全的返回地址。

### 我的专题足迹

- 分开展示“正在参与”和“历史参与”；
- 每条记录展示专题名称、加入时间、退出时间、当前活动状态；
- 进行中的专题提供详情与退出入口；
- 已结束专题展示归档状态，不提供事后修改。

### 后台与运营

- Django 后台新增报名记录列表，支持按专题、用户、状态和时间筛选；
- 专题后台列表显示活跃报名人数；
- 运营看板在专题表现中加入：
  - 当前活跃报名；
  - 统计周期内新增报名；
  - 报名人数与商品供给分开展示，不计算“报名转预约率”。

## 8. 服务层与并发策略

新增 `listings/campaign_registration.py`，视图不直接拼装状态变化。

- `join_campaign(user, campaign, now=None)`：
  - 校验专题仍在进行；
  - 在同一事务中检查当前活跃记录；
  - 已存在则返回“已经是报名状态”，不重复写入；
  - 不存在则创建新记录；
  - 若数据库唯一约束在并发中拦截，则回读活跃记录并按幂等成功处理。
- `leave_campaign(user, campaign, now=None)`：
  - 校验专题仍在进行；
  - 锁定并关闭当前活跃记录；
  - 已退出或从未报名时返回幂等结果，不更新时间戳。
- 服务返回结构化结果，至少包含 `changed`、`state` 和 `registration`，页面根据结果给出普通提示，不把并发冲突误报成系统错误。

## 9. 统计口径

- `active_registration_count`：当前 `is_active=True` 的记录数；
- `new_registrations`：统计周期内 `joined_at` 落在窗口中的记录数；
- 这两个指标都不等同于独立用户数，也不等同于订单数；
- 报名数只和专题级供给、浏览、收藏、预约并排展示；
- 样本不足时不输出“报名带来成交”的因果结论；
- CSV 导出沿用看板同一份构建器结果，不另写一套计算。

## 10. 测试清单

### 模型与服务

- 同一用户不能同时有两条活跃报名；
- 加入后再次加入不新增记录，也不改变加入时间；
- 退出后再次退出不改变退出时间；
- 退出后重新加入会创建新的参与区间；
- 专题未开始、已结束、已停用时加入或退出被拒绝；
- 活跃记录与 `left_at` 的一致性约束有效；
- 并发唯一约束失败时服务仍返回幂等结果。

### 页面与权限

- 匿名用户不能加入或退出；
- GET 请求不能改变报名状态；
- 已报名用户看到退出入口，未报名用户看到加入入口；
- 专题详情/列表只显示聚合人数，不出现报名用户名；
- 我的专题足迹只显示自己的记录；
- 非法 `next` 地址回退到专题详情；
- 外部站点地址不会被当作返回地址。

### 运营与后台

- 专题后台显示活跃报名数；
- 运营看板显示当前活跃报名和周期新增报名；
- CSV 与页面使用同一口径；
- 报名不会创建订单、通知或修改商品状态。
