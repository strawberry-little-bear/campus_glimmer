# README 视觉化展示设计

## 背景

README 已完成一次信息架构整理，正文从单页功能档案收缩为项目首页，详细规则进入 `docs/`。当前问题不再是信息缺失，而是首页仍以连续标题、表格和长段落为主，缺少可以快速建立产品印象的视觉入口。第一次打开仓库时，读者很难立刻看到系统实际长什么样，也不容易从八个业务模块中找到阅读节奏。

本次调整继续保持正常的长期迭代叙述，不把项目包装成一次性的重做或营销页。视觉元素用于帮助理解，不替代工程说明、运行方式、测试入口和文档索引。

## 目标

1. 首屏建立清晰的品牌识别：项目名、短定位、技术徽章和主要入口。
2. 用真实系统截图展示首页、商品发现、商品详情与通知中心，避免使用与实际界面无关的概念图。
3. 用留白、分隔线、图标化小标题和卡片式导航降低阅读压力。
4. 把八个业务模块压缩成可扫读的卡片或短表，完整规则继续链接到 `docs/feature-handbook.md`。
5. README 保持可维护：图片数量受控，截图路径集中，详细内容不在首页重复。
6. 继续使用 GitHub 原生 Markdown 能力，不引入需要额外构建步骤的文档系统。

## 视觉方向

### 色彩

截图与视觉装饰沿用站点当前主色：

| 用途 | 色值 |
| --- | --- |
| 深墨绿 | `#15251f` |
| 主色 | `#1d8a68` |
| 深主色 | `#146a50` |
| 薄荷底 | `#e8f6ee` |
| 暖白底 | `#fbfaf5` |
| 分隔线 | `#e5ece8` |
| 暖橙点缀 | `#f6aa61` |

README 中只使用少量彩色徽章和分隔线，避免每段都加粗、加色而重新形成视觉噪声。

### 版式

1. 顶部使用居中品牌区、短句、徽章和简洁锚点导航。
2. 首页大图作为产品主视觉，占主要宽度。
3. 三张次要截图使用表格并排展示；GitHub 窄屏下按阅读顺序自然换行。
4. 功能入口改为八个小节或双列卡片，每个入口只保留一句能力和一个文档链接。
5. 工程、运行、测试与部署继续使用常规标题和短代码块，保证可直接复制。
6. 文档地图放在靠后位置，避免技术细节打断产品预览。

## 截图策略

- 截图来自本地运行中的真实 Django 页面，使用演示数据，不伪造界面。
- 以 `1440 × 1120` 浏览器窗口启动，实际导出 `1424 × 969` 的桌面视口，使用浅色主题和站点现有字体。
- 首页截图展示品牌主视觉和首屏信息结构。
- 发现页展示分类、交易地点筛选和商品卡片。
- 商品详情展示图片、价格参考、场景标签和交易操作。
- 通知中心展示未读统计、类型分布、筛选和批量操作。
- 图片统一注明“界面预览 · 本地演示数据”，避免被误认为线上生产数据。
- 截图保存在 `docs/screenshots/`，文件名使用稳定的英文短名，便于 README 长期引用。
- 截图只作为展示资源提交，不提交生成脚本、浏览器依赖、演示数据库或临时上传文件。

## 信息层级

### 第一层：快速判断

品牌名、单句定位、技术栈、CI 状态、产品主截图。

### 第二层：理解系统

四张真实界面截图、八条业务链路、一张端到端流程图。

### 第三层：运行和维护

本地启动、环境变量、Docker、测试、定时任务、权限与安全。

### 第四层：深入阅读

功能手册、数据模型、模块地图、部署与边界文档、路线图和历史设计说明。

## 非目标

- 不修改业务代码、页面样式、数据模型或本地数据库。
- 不使用生成的虚构产品截图代替真实页面。
- 不把 README 改成纯宣传页，不删除工程和运维入口。
- 不恢复长篇功能罗列，完整规则仍然由 `docs/` 承担。
- 不新增需要额外渲染服务的 Markdown 扩展。

## 验收标准

1. 首屏能够看到项目名、短定位、徽章和真实首页截图入口。
2. README 至少包含首页、发现页、商品详情和通知中心四张有效图片。
3. 图片路径全部存在，替代文本和演示数据说明完整。
4. 八条业务链路仍可从首页一次点击进入对应文档章节。
5. 本地运行、Docker、测试、文档地图和参与开发入口不丢失。
6. README 不再出现连续密集长表或大段无分组说明。
7. `git diff --check`、图片路径检查和 Django `manage.py check` 通过。
8. 设计、文档与业务代码分开提交，便于回溯视觉改版。
