# 贡献里程碑事件台账

状态：已落地
实现模块：`listings/contributions.py`、`listings/models.py`、`listings/migrations/0075_contributionmilestoneevent.py`、`listings/migrations/0075_backfill_contribution_milestones.py`
新增事实表：贡献等级 / 徽章首次达成事件
后续读者：运营看板的跨周期里程碑对照

## 1. 要回答的问题

贡献积分体系已经能回答「现在有多少人在每一级、每一枚徽章」，但它回答不了：

> 这一批等级和徽章是什么时候被跨过的？本周期和上一周期相比，达成节奏是变快、变慢，还是只是总量变大？

当前库里只有一条条 `CommunityContribution` 积分流水。等级和徽章都是从流水实时汇总出来的累计状态。把今天的状态按注册时间、贡献时间或落库时间切到历史周期里，都会把「一直保持第三级」的人误读成「那个周期升到第三级」。所以要补一张只记录状态跃迁的事实表。

## 2. 事件口径

一条里程碑事件只表示一次从「未达成」到「已达成」的跃迁：

- **等级事件**：用户本次新增贡献前总积分低于某级门槛，加入本条贡献后达到或越过该门槛。
- **徽章事件**：用户本次新增贡献前对应指标低于徽章门槛，加入本条贡献后达到或越过该门槛。
- 徽章指标继续复用产品侧规则：总事件数或指定贡献类型的事件数，不在台账里另造一套判断。
- 每个用户同一里程碑只允许一条事件，用唯一约束兜底。
- 事件时间取触发跃迁的那条贡献的 `occurred_at`，不用数据库落库时间冒充业务发生时间。

如果一次贡献同时跨过多个门槛，例如一个较大分值同时跨过两级，或多枚徽章同时首次达成，就写多条事件。事件表示里程碑，不表示一次通知或一次庆祝。

## 3. 写入时机与幂等

台账写入挂在现有 `record_contribution` 的幂等路径之后：

1. 先按 `source_key` 执行现有 `get_or_create`；
2. 只有该贡献记录是本次新建时，才计算写入前的累计值；
3. 加入新贡献后重新计算等级与徽章指标；
4. 对所有从低到高完成首次跨越的门槛写入事件；
5. 重复业务事件命中已有 `source_key` 时不补写、不更新、不改时间。

计算和写入放在同一个数据库事务里，并锁住对应用户行，串行化同一用户的贡献写入，避免两条并发贡献都看到相同的写入前累计值。台账唯一约束是最后防线，即使未来绕过公共写入函数，也不能出现同一用户同一里程碑的两条首次达成事件。

## 4. 历史回填

新增表后需要回填既有贡献流水：

- 每个用户按 `occurred_at`、`id` 的稳定顺序重放积分与徽章规则；
- 首次跨过门槛时生成事件，事件仍指向触发跨越的那条贡献；
- 回填事件标记为 `backfilled`，与后续在线写入事件区分；
- 同一时间的多条贡献按 `id` 排序，这是可解释的稳定规则，不宣称它能恢复真实先后。

回填是数据迁移，不补通知、不发庆祝、不写用户可见动态。历史事件的时间来自原贡献流水，不来自迁移执行时刻。

## 5. 规则演进边界

- 事件保存达成时的门槛、标题和指标值，未来规则改名或调门槛时，历史事件仍保留当时的解释；
- 新事件始终按当前产品规则计算；
- 若门槛下调，已经高于新门槛的用户不能靠下一次真实贡献自然触发，后续需要专用回填按历史流水重建；
- 若门槛上调，已保存事件不删除，当前等级分布仍由产品侧规则实时计算；
- 台账不反向修改贡献流水，也不自动调整用户当前等级。

## 6. 隐私与产品边界

- 事件只作为运营统计事实，不进入公开个人页；
- 不发放额外积分，不触发通知、弹窗、庆祝动效或排行榜；
- 运营面板只输出聚合与样本量，不输出用户名、联系方式或贡献描述；
- 不把「升级慢」解读为用户 inactive：积分来自特定互助行为，交易频繁但不参与赠送、求购响应或失物线索的用户不会快速升级。

## 7. 测试与验收

- 单条贡献跨过一级时写入一条等级事件；
- 一次贡献跨过多个等级时写入多条事件；
- 徽章按总事件数和指定类型分别验证；
- 重复 `source_key` 不产生第二套事件；
- 两个用户互不影响；
- 事件时间取贡献业务时间；
- 历史回填按时间与 ID 稳定重放，并标记回填；
- 里程碑唯一约束可防止重复写入；
- 现有贡献汇总、等级判断和徽章展示不变。

## 8. 落地记录

- 新增 `ContributionMilestoneEvent` 事实表，保存等级与徽章首次达成时的门槛、跨越前后指标、业务时间和是否回填。
- `record_contribution` 在同一事务内串行化同一用户写入，并复用产品侧等级与徽章规则生成里程碑。
- 数据迁移按 `occurred_at`、`id` 稳定回填历史流水；零分等级是默认状态，不生成伪里程碑。
- 台账不进入公开个人页，不发通知、不发积分、不生成排行榜；跨周期运营面板等事件覆盖稳定后再做。
